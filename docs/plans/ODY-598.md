- **`<pre class="hljs">` appears 195 times** and `<li><p>` in 78 rows. Both come from the frontend's TipTap editors, not CKEditor. CKEditor's CodeBlock writes `<pre><code class="language-x">`.
- **Images:** every `img src` is absolute https (`content.khouryodyssey.org` or `odyssey-dev-bucket.s3.us-east-2.amazonaws.com`).
- **No backend code reads or writes the 5 fields** (lifecycles and the custom-lesson controller were checked).

**The bar (v5-only baseline, user decision).** Any CKEditor without GeneralHtmlSupport rewrites markup it has no plugin for when someone saves, and v4 did this too. So "a save round-trip is byte-identical" is the wrong bar. The bar is:

1. **Booting with the plugin changes no stored value** (fingerprints).
2. **The frontend render is unchanged** compared with the stand-in baseline. Since the stored values don't change, nothing should.
3. **An admin open-and-save keeps the rendered text identical** (`innerText` on the frontend). Every HTML change is explained, and it's acceptable only if it's markup the v4 preset couldn't represent either (lists above), such as `hljs` classes or `<li><p>`. Anything else is a regression.

## Design Decisions

1. **No data migration by default.** The values are HTML in `text` columns, and both candidate plugins register type `richtext`. So the change touches `schema.json` only. A migration (T1.5) is written only if T1.4 or T1.6 finds a regression that a data rewrite fixes better than a preset change.
2. **Presets `light`/`rich` match v4 feature for feature, with two user-approved changes:**

   - **No MediaEmbed.** The site strips `<oembed>`, so embedded videos never show.
   - **`codeBlock.languages`** = CKEditor's defaults (plaintext first, then c, cs, cpp, css, diff, html, java, javascript, php, python, ruby, typescript, xml) **plus bash, sql and json**. The data has 30 bash, 1 sql and 1 json blocks, which v4's default list would have flattened to plaintext on save.

   No `StrapiUploadAdapter` (v4 had only the Media Library button) and no GeneralHtmlSupport. **Don't add features beyond v4's:** the frontend has no CKEditor CSS (`.ck-content`, `image-style-*`, `marker-*`, `text-*` are unstyled) and sanitizes with DOMPurify defaults, which strip `<oembed>` and `<iframe>`.

3. **Plugin: the fork `@_sh/strapi-plugin-ckeditor`, pinned exactly to `8.0.0`** (user decision; supervisor approved). Field id `plugin::ckeditor5.CKEditor`, self-hosted, `licenseKey: "GPL"` in each preset's `editorConfig`. The official plugin was rejected because of its CDN, licence key and 1,000-load monthly cap. Also add `ckeditor5` as a direct dependency, pinned to the exact 48.4.x version the fork resolves, so `app.tsx` imports resolve and there's no duplicate CKEditor.
4. **Fingerprints, not eyeballing.** Per column: `data_type`, count, non-null and non-empty counts, `sum(length)`, and an id-free fingerprint `md5(string_agg(coalesce(col,'<null>'), ',' ORDER BY md5(coalesce(col,'<null>'))))`, the same SQL as ODY-597. Also an id fingerprint (`ORDER BY id`); ODY-597 found ids unchanged by the v4→v5 boot. Follow ODY-633's SQL style: `\set ON_ERROR_STOP on`, `\echo` headers, a read-only file. Output goes outside the repo.
5. **Scratch DB: `ody598` only**, cloned from `ody633`. The first boot of this branch on it (T0.5, stand-in) does the v4→v5 migration. T1.6 re-clones it, so its last run is a direct v4 → v5-with-plugin migration, which is the path prod will take. `ody633` and `ody597` are never written by this ticket.
6. **v5-only baseline (user decision).** The "before" state is this branch with the richtext stand-in. No v4 code is booted.
7. **Documentation plugin dropped** (user decision). Nothing in the repo uses it, Strapi marks it unmaintained for v5, and the dev DB has `restrictedAccess: false`, so it publicly exposes the API schema. Re-adding it later is one install.
8. **Round-trip bar** (user decision): a Strapi save may rewrite markup CKEditor can't represent (the `hljs` class, `<li><p>`, the inline-math span), as long as the site's `innerText` stays identical. Checked effects: the site colours code from `language-x`, not `hljs`; math renders from the `$…$` text, which survives; `<li><p>` → `<li>` may tighten list spacing slightly.
9. **Real content stays in `~/ody-598/`**: SQL output, rendered HTML, screenshots, sample ids and round-trip diffs. The repo gets only aggregate counts.

## Constraints Discovered

- **CSP** (`config/middlewares.ts:3-27`): `connect-src` = `'self' https:`, `img-src`/`media-src` = `'self' data: blob: market-assets.strapi.io AWS_CDN_URL`, and no `script-src`. **Verified:** Strapi 5 merges CSP directives with its defaults position by position, not by appending. Any directive we set must be written out in full, including `'self'`. There's no `odyssey-dev-bucket…amazonaws.com` host either, so admin previews of dev-bucket images may be blocked. Note it, don't fix it.
- **Typegen runs on every `develop`** and rewrites `types/generated/*.d.ts`. After each boot, `git diff --stat backend/types` should show only the expected attributes.
- **The stand-in admin is a Markdown editor.** During T0.5 nobody saves any of the 5 fields in the admin.
- **`/draft` routes write:** the v1 draft lesson editor re-PUTs the whole block array after mount (`components/draft/lesson/lesson-renderer.tsx:205-211`). Never open `/draft` routes during captures.
- **The documentation plugin writes into `src/`** (`public/index.html`/`login.html`) whenever `/documentation` is opened. Revert that churn unless T2.3 says otherwise.
- The Docker `strapi` and `frontend` containers must stay stopped (the boot script checks for `strapi`).

## Edge Cases

- Empty or NULL values: `overview` is NULL on 92 of 133 rows. A few generic and question rows are the empty string. Fingerprints use `coalesce`, and samples include one empty overview.
- No overview contains a code block (the earlier count was a URL false positive), so the `light` preset's lack of CodeBlock loses nothing.
- Inline math (`data-type="inlineMath"`, plus 2 rows with `\(` or `$$`): the lesson and presentation renderers regex-replace `$…$`/`$$…$$` in the raw HTML and render with KaTeX. Pick one math sample, and one with a literal `$` if one exists.
- `<oembed>` (1 generic row): no frontend code converts it, and DOMPurify strips it, so it renders nothing today. Check that it still renders nothing and doesn't break the block. The fork's CKEditor 48 changes media-embed output on save.
- Tables (13 generic rows, 1 question row): the fork's CKEditor 48 writes alignment as classes and adds `scope` on header cells when saving. Include at least two table samples.
- Highlights and notes depend on rendered text. Offsets are `TreeWalker(SHOW_TEXT)` character counts over the lesson container after DOMPurify, KaTeX, hljs and the line-number gutter (`generic-block-renderer.tsx:296-372, 451-480`). That's why bar 3 requires an identical `innerText`.
- `required` is restored exactly as in v4 (`overview` `false`, open-ended no key).
