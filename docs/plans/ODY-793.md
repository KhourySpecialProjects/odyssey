## Problem

The scan's Media and accessibility column has 9 checks and 19 rules: alt text, vague link text, long headings, images, videos, links, quizzes, open-ended questions, code blocks, datasets and the fun fact. Four of them (Images, Videos, Links, Datasets) have to visit URLs through ODY-789's safe fetcher. The rules exist only in Brady's prototype, which runs on made-up data in a browser. They need porting to TypeScript against Odyssey's real block formats, real hosts, real code runner and real dataset model, in a way that ODY-790's runner can drive without knowing what any rule does.

## How the code works now (verified on this branch; the tasks rely on these facts)

- **The fetcher** (`frontend/lib/overview-scan/network.ts`, ODY-789) starts with `import "server-only"`. It exports `FetchUrl = (url) => Promise<UrlCheck>` (never rejects) and `UrlCheck` = `loaded` (status, `contentType`, `bytes | null`) | `broken` (`status | null`) | `refused` (`invalid-url` | `unsupported-scheme` | `private-address`) | `unchecked` (`timeout` | `budget` | `too-many-redirects` | `rate-limited` | `network-error`). It caches by the exact input string, so two rules asking for the same URL share one request. Rules must use `import type` only (ODY-789 D8).

## Design Decisions

- **D1. Contract first: ODY-793's first PR creates `types.ts`, a media-only `config.ts`, `text.ts` and the sample fixture; ODY-790 extends them (recommended; Open Question 1).**

  - **Why:** ODY-790 hasn't started, and it waits on ODY-788. ODY-793's shapes are small and come straight from the prototype. Waiting would idle ODY-793 for an unknown time.
  - **What ODY-793 creates** (under `frontend/lib/overview-scan/`):
    - `types.ts`: exactly the `[CONTRACT]` types and the `flag()` helper.
    - `config.ts`: a `CONFIG` object with only the media keys, using the prototype's key names so ODY-790 can add the rest without renaming.
    - `text.ts`: the prototype's `words` and `norm`, which ODY-791 needs too.
    - `frontend/testing/mocks/overview-scan.ts`: the prototype's sample droplet as a `ScanDocument`, plus small factories. ODY-790, 791, 792 and 796 reuse it.
  - **If ODY-793 lands first** (likely):
    - ODY-790 builds `snapshot.ts` to produce these shapes and `run.ts` to consume them.
    - It adds the block types the other checks need (`list`, `callout`, …) to the `ScanBlock` union, its own fields to `ScanPart`, and the other keys plus `RULES_VERSION` to `CONFIG`.
    - It must not rename or narrow anything in the contract without telling ODY-793's developer. Adding is free.
    - ODY-790 adds one test: `runChecks(sampleScanDocument, MEDIA_CHECKS, stubFetch)` gives Accessibility and Links "needs attention" and the other seven "passed". That proves the status mapping end to end.
  - **If ODY-790 lands first:**
    - ODY-793 rebases onto it, drops its own `types.ts` / `config.ts` / `text.ts` additions, and adapts `media.ts` to ODY-790's names.
    - If ODY-790 adopted the contract, that's zero changes.
    - If ODY-790 chose different names, ODY-793 adapts (ODY-790 owns them), but the fields in the contract table must still exist in some form.
  - **Alternatives:**
    - **A private types file** (`rules/media-types.ts`) that ODY-790 later replaces. No conflict risk, but two shapes drift apart and ODY-791/792 can't use it.
    - **Build on ODY-790's branch once it exists.** Cleanest ownership, but it blocks this ticket on two others.

- **D2. A rule reports couldn't check with an `"unknown"` flag; `runChecks` owns every status (as in the prototype).**

  - A rule returns `Flag[]`. Each flag has `severity: "warn"` (needs attention) or `"unknown"` (couldn't check).
  - **`runChecks` computes** (the prototype's `statusOf` / `evaluateCheck`):
    - a rule is _needs attention_ if any flag is `"warn"`, _couldn't check_ if it has only `"unknown"` flags, and _passed_ with no flags;
    - a check is the worst of its rules, with needs attention above couldn't check above passed.
  - **So a timed-out URL gives a gray flag that still opens the block it's in.** The UI can say "this link didn't answer within 5 s" rather than just a gray circle.
  - **The ticket's sentence** ("When the safe fetcher returns couldn't check for a URL, the check reports couldn't check, not needs attention") is read per URL: an unchecked URL never makes a yellow flag. A check where one link timed out and another is broken is still yellow, because the broken link really needs attention. That's the prototype's precedence (Open Question 6).
  - **Rules never throw on well-typed input** (they treat missing text as empty), and `fetchUrl` never rejects. If a rule throws anyway, ODY-790's ticket already says the check becomes couldn't check.
  - **Alternative:** rules return `{ flags, unchecked: boolean }`. It loses the per-URL message and block link for gray results.

- **D3. URLs are classified before any fetch. The mapping lives in one helper.**

  - **`urlFlag(part, blockId, what, result)`** turns a `UrlCheck` into a flag or `null`:

    | Result                            | Severity | Message (`what` = "This image", `The link "guide"`, …)                  |
    | --------------------------------- | -------- | ----------------------------------------------------------------------- |
    | `loaded`                          | none     | the caller applies its own test                                         |
    | `broken`, status `404`            | warn     | `… doesn't load (404 Not Found).` (the prototype's `STATUS_TEXT`)       |
    | `broken`, status `null`           | warn     | `… doesn't load: the site doesn't exist.`                               |
    | `refused`, `private-address`      | warn     | `… wasn't fetched: private or internal address.` (the prototype's text) |
    | `refused`, `unsupported-scheme`   | warn     | `… wasn't fetched: not a web address.`                                  |
    | `refused`, `invalid-url`          | warn     | `… wasn't fetched: not a valid web address.`                            |
    | `unchecked`, `timeout`            | unknown  | `… didn't answer within 5 s.` (the prototype's text)                    |
    | `unchecked`, `budget`             | unknown  | `… wasn't checked before the scan's time ran out.`                      |
    | `unchecked`, `too-many-redirects` | unknown  | `… redirects too many times to check.`                                  |
    | `unchecked`, `rate-limited`       | unknown  | `… asked us to slow down (429), so it wasn't checked.`                  |
    | `unchecked`, `network-error`      | unknown  | `… couldn't be reached.`                                                |

    `switch (result.kind)` and `switch (result.reason)` are exhaustive (`satisfies never`), so a new fetcher reason fails the type check here.

  - **The "5 s"** is a literal, as in the prototype. `media.ts` can't import `NETWORK_LIMITS` without loading `node:http` in tests. When ODY-790 moves the limits into `config.ts` (ODY-789 D10), derive it.
  - **Before fetching, each rule sorts its URLs (Open Question 7):**
    - **Internal links** (`/…`, `#…`, `?…`) are Odyssey pages. All three link rules skip them. They work for students, and fetching the app from the server would be refused anyway.
    - **`mailto:` and `tel:` links** aren't web links. All three link rules skip them (the link-text rule still reads their text). Fetching them would give `unsupported-scheme`, a false yellow.
    - **A relative image or dataset URL** (`/uploads/…`) only happens in local dev. It's an `"unknown"` flag: `… has a relative address (/uploads/x.csv), so it wasn't checked.` No fetch.
    - **`data:image/…` images** (legacy TipTap allows base64) load by definition. No fetch. The size is the decoded length, `floor(base64Length × 3 / 4)`.
    - **Anything else**, including `www.example.com` with no scheme (a broken relative link in a browser) and `javascript:`, goes to the fetcher. Its `refused` result is yellow.

- **D4. Network rules fetch in parallel and report in document order.**

  - The prototype `await`s each URL inside its loop, so one rule's 30 links take up to 30 × 5 s, one at a time, and the fetcher's 6-wide queue sits idle.
  - Each network rule collects its targets in document order, runs `await Promise.all(targets.map((t) => fetchUrl(t.url)))`, then builds flags in the same order. The output is deterministic.
  - The Images `loads` and `size` rules ask for the same URL strings, so the fetcher's cache makes one request per image.
  - **For ODY-790:** run checks concurrently too (`Promise.all` over checks, results kept in check order). The fetcher's queue and 20 s budget already bound the network.

- **D5. Videos: YouTube and Vimeo through oEmbed, everything else directly (Open Question 5).**

  - **`allowed-host`** (offline): the host must be in `CONFIG.videoHosts` (the prototype's 5: `www.youtube.com`, `youtube.com`, `youtu.be`, `vimeo.com`, `player.vimeo.com`), or be Odyssey's own media host (D6).
  - **`exists`** (network) picks a target:
    - **YouTube host:** parse the video id with `URL`:
      - `youtu.be/<id>`;
      - `?v=<id>`;
      - `/embed/<id>`, `/shorts/<id>`, `/live/<id>` or `/v/<id>`.
      - Fetch `https://www.youtube.com/oembed?url=<encoded https://www.youtube.com/watch?v=<id>>&format=json`.
      - Canonicalizing matters: the legacy editor saves every video as `/embed/<id>`, and the BlockNote converter passes `/shorts/` URLs through unchanged.
      - **No id** (the legacy editor's placeholder `https://www.youtube.com/`, or a channel page): `"warn"`, `This video link doesn't point at a YouTube video.`, with no fetch.
      - A private video gives 401 or 403 from oEmbed, which the fetcher reports as `broken`, so it's yellow. A deleted video gives 400 or 404, also yellow.
    - **Vimeo host:** `https://vimeo.com/api/oembed.json?url=<encoded original URL>`. Vimeo answers 403 for a private video and 404 for a missing one. Its oEmbed takes both `vimeo.com/<id>` and `player.vimeo.com/video/<id>`.
    - **Anything else** (CDN or not allowed): the URL itself, through the fetcher. `loaded` passes. As in the prototype, a disallowed host still gets its existence checked, so the creator sees both problems at once.
  - **Known false yellow:** a Vimeo video with embed privacy limited to certain domains answers 403 even if Odyssey's domain is allowed. That's rare, and the flag tells the creator exactly which video to check.

- **D6. Odyssey's media hosts come from env at run time (Open Question 4).**

  - `odysseyMediaHosts(env = process.env)` returns the hostnames of `env.AWS_CDN_URL` and `env.AWS_S3_BUCKET_URL` (skipping unset or unparsable ones). It's the same pair, and the same reasoning, as `next.config.mjs`'s `datasetOrigins`: the list follows the real bucket or CloudFront distribution without edits.
  - It's called inside the rule's `run`, not at module load, so tests set `process.env` in `beforeEach`.
  - Both are server env vars set in every deployed frontend (Strapi's upload `baseUrl` and the frontend's upload URLs use them). Locally they may be unset, which only means a local CDN video gets flagged.
  - The env-var **names** go in `CONFIG.mediaHostEnv`. No values are read at build time.
  - **Alternative:** the literal bucket hosts from the Dockerfiles. Simple, but it goes stale the day the CDN moves, and `next.config.mjs` explicitly chose not to do that.

- **D7. Datasets "has rows" works with today's data, where `rowCount` is always `null` (Open Question 2).**

  - **The rule** (`loads`): fetch `fileUrl`, then map with `urlFlag` per D3. Once it's `loaded`, flag `The dataset "<name>" has no rows.` when either:
    - `rowCount === 0`; or
    - `rowCount` is `null` and the fetch says `bytes === 0` (an empty file).
  - Otherwise it passes, including `rowCount: null` with `bytes: null`.
  - **Why not the prototype's `!(rowCount > 0)`:** it would flag every dataset ever uploaded, because `datasetSchema` strips `rowCount` (see "How the code works now"). A check that's always yellow teaches reviewers to ignore it.
  - **Follow-up ticket** (for the user to file): store `rowCount` and `columnCount` at upload. `dataset-upload.tsx` already parses them; `datasetSchema` and `createDataset` need two optional fields. Then this rule tightens to the prototype's test with no change to the contract.
  - **`used`** (offline): each dataset's `name` must appear as a substring in at least one `code` block's `code` (both variants: code and notebook), as in the prototype. Sandpack files are browser JavaScript and can't read datasets, so they don't count.

- **D8. The language rule checks only what the runner runs (Open Question 3).**

  - **Runnable `code` blocks** (`variant: "code"`, `runnable: true`): `language` must be in `CONFIG.codeLanguages`, which is `RUNNABLE_LANGUAGES` (the keys of `LANGUAGE_CONFIG`).
    - Flag: `The code runner doesn't support "<language>".`, or `This code block has no language set.` when `language` is `null`.
  - **Display-only code blocks** (`runnable: false`, including every legacy `<pre><code>`): not checked. A `json` or `sql` snippet shown for reading is fine, and the runner never touches it.
  - **Notebook blocks:** not checked. They always run Python, whatever their `language` prop says.
  - **Sandpack blocks:** `template` must be in `CONFIG.sandpackTemplates` (`vanilla`, `react`, `react-ts`). Flag: `Sandpack doesn't support the "<template>" template.`
  - **One list:** Task 1 moves `LANGUAGE_CONFIG` out of the `"use client"` file into `frontend/lib/code-languages.ts` (no directive), which `code-execution.ts` and `config.ts` both import. The editor's `SUPPORTED_LANGUAGES` and `/api/run-code`'s `ALLOWED_LANGUAGES` stay as they are (out of scope).
  - **`has-code`:** `code` and notebook blocks need non-blank `code` (`This code block is empty.` / `This notebook block is empty.`). A Sandpack block needs at least one file with non-blank content (`This Sandpack block has no files with code.`). An empty `files` object counts as empty even though Sandpack would show its template's starter files, because the rule text asks for content. The prototype's code only checked `code` blocks; the ticket and the prototype's rule text cover all three.
  - **Alternative:** the prototype's `codeLanguages` on every block. It would flag every `json` display block and pass `sql`, `html` and `css`, which Odyssey can't run.

- **D9. Small rule decisions, each matching the prototype unless noted.**

  - **Captions:** an `image` block's `caption` must be non-blank. For legacy `<img>`, ODY-790 puts the `alt` attribute in `caption` (the field screen readers actually get).
  - **Link text:** `norm(text)` is in `CONFIG.vagueLinkText` (the prototype's 5, including `"read more"`), or is a bare URL. "Bare URL" is `^https?://` as in the prototype, plus `^www\.` (new; it doesn't change the sample). It applies to block links only, not next steps, as in the prototype.
  - **Heading length:** `words(text).length > CONFIG.maxHeadingWords` (12).
  - **Image `loads`:** if `contentType` doesn't start with `image/` (including `null`), flag `This URL loads, but it isn't an image.`

import type { FetchUrl } from "./network"; // type-only: network.ts is server only

/** A link anywhere in a block's text. `url` is the raw href, trimmed. */
export type ScanLink = { text: string; url: string };

/** Every string is plain text: HTML stripped, entities decoded, whitespace collapsed. */
type BlockBase = {
  id: string; // BlockNote uuid, or the legacy component's id; may repeat when one
  // legacy block yields several (e.g. two <img> in one generic block)
  links?: readonly ScanLink[]; // every link in this block's text, in order
};

export type ScanBlock = BlockBase &
  (
    | { type: "heading"; level: number; text: string }
    | { type: "paragraph"; text: string } // the droplet page's overview is { id: "overview" }
    | { type: "image"; url: string; caption: string } // legacy <img>: caption = alt
    | { type: "video"; url: string }
    | {
        type: "quiz-mc"; // one per question; legacy true/false stays quiz-mc
        question: string;
        options: readonly { text: string; isCorrect: boolean }[];
      }
    | { type: "quiz-tf"; question: string; correctAnswer: boolean } // BlockNote only
    | { type: "quiz-open"; question: string; correctAnswer: string }
    | {
        type: "code";
        variant: "code" | "notebook";
        language: string | null; // null = not stated (legacy <pre><code> with no class)
        code: string; // raw source, NOT whitespace-collapsed
        runnable: boolean; // legacy: false; notebook: true
      }
    | {
        type: "sandpack";
        template: string;
        files: Readonly<Record<string, string>>; // parsed from the JSON string; {} if unparsable
      }
  );
// ODY-790 adds the members ODY-791/792 need (list, callout, …). Media rules
// filter by `type`, so extra members never break them.

export type ScanPart = {
  id: string; // "droplet" for the droplet page; the lesson's numeric Strapi id as a string otherwise
  kind: "droplet" | "lesson";
  title: string; // "Droplet page", "Lesson 2 · Finding missing values"

};

export type ScanDataset = {
  name: string;
  fileUrl: string; // absolute S3/CDN URL, or "/uploads/…" locally

  funFact: string; // "" when unset

  droplet: ScanDroplet; // ODY-790 adds the fields ODY-791/792 need

  partId: string;
  blockId: string | null; // a block id, or a droplet field id ("next-steps", "datasets", "fun-fact", …)
  message: string;
  severity: FlagSeverity;
};

  id: string; // unique within its check
  text: string;

};

export function flag(
  part: ScanPart,
  blockId: string | null,
  message: string,
  severity: FlagSeverity = "warn",
