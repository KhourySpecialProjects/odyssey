## Reachability facts (from code read during planning)

- **Deployed containers never run `strapi develop`.** Both ECS images (`backend/ecs.prod.Dockerfile`, `backend/ecs.dev.Dockerfile`) end in `CMD ["npm", "run", "start"]`, which is `strapi start`. `prod-image-push.yml` and `dev2-image-push.yml` build only those files, and they change only `.image` in the task definition. `terraform/` has no `command` override. Only the local `backend/Dockerfile` (docker-compose) runs `npm run dev`.
- **`strapi build` runs Vite as a bundler, not as a dev server.** The image build runs it, and the default bundler is vite (`@strapi/strapi/dist/src/node/create-build-context.js:122`). The vite and esbuild advisories are all about the dev server (`server.fs.deny`, optimized-deps `.map` serving, the launch-editor middleware, and the esbuild serve CORS issue).
- **webpack-dev-middleware only loads under `strapi develop --bundler=webpack`** (`develop.js:111`). We use the default, which is vite.
- **Email.** `backend/config/plugins.ts` has no `email` block, so Strapi falls back to `@strapi/provider-email-sendmail`. That provider does direct MX delivery on port 25 through `nodemailer.createTransport` + `sendMail` + `close` (`provider-email-sendmail/dist/direct-smtp.js:77-108`). No app code in `backend/src` sends mail. The frontend never calls `/api/auth/local*`, `forgot-password` or `send-email-confirmation`, and `up_users` has 0 rows (ODY-600). So the only real triggers are admin forgot-password, which sends to a **stored** admin address, and the admin-only "Send test email" button. An unauthenticated attacker can't get a crafted address list into `addressparser`.
- **braces** (no patched release exists):
  - `chokidar`: lazy-loaded only in `@strapi/strapi/dist/src/node/develop.js:28,292` (the file watcher). Its patterns are the project cwd plus fixed ignores.
  - `micromatch` in `@strapi/content-type-builder`: used only in the **admin browser bundle** (`dist/admin/components/AIChat/hooks/useCodeUpload.js:40`), with constant ignore patterns. The worst case is an admin hanging their own tab.
  - `@strapi/utils` → `preferred-pm` → `find-yarn-workspace-root2` → micromatch: package-manager detection. Its patterns come from the local `package.json` workspaces, not from requests.
  - `plop`/`liftoff`/`findup-sync` (generators), `jscodeshift` (codemods) and `fork-ts-checker-webpack-plugin` (build/develop typecheck) are all CLI or build-time only.
  - No server request path passes user input to braces or micromatch.

## Design Decisions

- **D1: The decision record lives in this plan doc only.** It's the table above. `docs/agent/testing-and-deployment.md` gets a ~5-line pointer (Task 4). No separate backend doc, because the plan already is the record.
- **D2: Overrides follow the existing `backend/package.json` `overrides` style.** That means top-level, unscoped package names. There's exactly one nodemailer, dompurify and markdown-it consumer chain, so scoping adds nothing. Keep keys roughly alphabetical among the unscoped entries.
- **D3: The dependency-alert path is a manual `npm audit` at merge time (recommended), with an optional temporary Dependabot entry.** Reasons:
  - Dependabot reads `.github/dependabot.yml` **only from the default branch**, which is `production` (`origin/HEAD` → `production`). Adding a `target-branch: "feature/strapi-v5"` entry on this branch does nothing. It would have to go through a separate `develop` PR and then a `develop` → `production` release, and v5 may merge to `develop` before that happens.
  - Dependabot **security** updates only ever target the default branch. A `target-branch` entry only gets weekly **version** bumps. Those can't fix the transitive pins that cause these findings (Strapi pins exact versions), and they'd add PR noise mid-migration.
  - Running `npm audit` at each `develop` → `feature/strapi-v5` merge, and once before the ODY-602 rehearsal, works immediately and costs nothing. The rule: any advisory **name** not in the Decision Record must be triaged before the merge commit lands.
  - If Q3 = "also add Dependabot", the exact entry is in the "Optional Dependabot entry" section below. GitHub allows several entries for the same ecosystem and directory as long as their `target-branch` values differ. The current file already has one `/backend` entry targeting `develop`. Remove the temporary entry in the same PR that merges `feature/strapi-v5` into `develop`.
- **D4: Fix the root lockfile with plain `npm audit fix` (no `--force`).** It moves `typescript-eslint` to 8.71.0, which is inside `^8.32.0` and uses tinyglobby instead of fast-glob, so braces drops out. The ticket author verified 0 vulnerabilities on a scratch copy. Root CI runs on **Node 18**, so check typescript-eslint's `engines`.
- **D5: Smoke-test nodemailer at the provider level, not through a full Strapi boot.** A scratchpad script drives `@strapi/provider-email-sendmail` against a local SMTP sink. That exercises exactly the nodemailer calls that changed, needs no DB or `.env`, and adds nothing to the repo. The user does a full `npm run develop` boot as the final check.

## Side finding (not in scope, for the user)

The sendmail provider delivers directly to recipient MX servers on port 25 from Fargate. AWS restricts outbound port 25 by default, so admin password-reset mail may not work in prod today. Nobody has verified this. If working mail matters, open a follow-up to configure SES through `@strapi/provider-email-nodemailer` or the Amazon SES provider.
