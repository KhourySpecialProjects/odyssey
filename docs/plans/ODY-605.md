## Problem

## How the code runs now (verified 2026-10-06; the docs must say this)

- **Backend:** `@strapi/strapi` 5.56.0. Node `>=20 <=26`; images run 20.14.0 (ODY-604). `entityService` appears 0 times in `backend/src`, and `tests/no-entity-service.test.js` enforces that.
- **Data access:** the Document Service (`strapi.documents(uid)`) in the droplet and lesson lifecycles and the lock routes. The Query Engine (`strapi.db.query`) is used only inside `strapi.db.transaction` in `custom-lesson.ts` `acquireLock`.
- **Hooks:** v4-style `lifecycles.ts` (droplet, lesson, playlist, creation-request, access-request), tested on v5 (ODY-599/606). No document middlewares anywhere. Bulk `*Many` lifecycle hooks never fire from the Document Service. The v5 upgrade codemod comments lifecycle files out.
- **D&P:** `draftAndPublish: false` on all 23 API types and on the users-permissions user. Droplet and voyage have a real `status` enum. v5 reserves `status` only on D&P types: boot only warns (only `id`/`document_id` collisions throw), and the Content-Type Builder refuses to create a new `status` attribute. Like v4, v5 deletes rows with `published_at IS NULL` when D&P is turned off, and it keeps the column. The content-manager extension (`backend/src/extensions/content-manager/`, ODY-699) keeps the real `status` visible in the admin.
- **Strict REST:** an unknown query or body key returns 400 "Invalid key", with `error.details.source` = `query` or `body`. Guard: `frontend/testing/contract/strapi-query-catalog.test.ts`. `regenerateSlug` is allow-listed for **PUT only**, via `strapi.contentAPI.addInputParams` in `backend/src/index.ts` (ODY-700). A POST with it still gets a 400. Dynamic-zone nested populate needs `on: { "<component>": {...} }` per component (`frontend/lib/requests/lesson-populates.ts`). Without it you get a 400, or the component is silently dropped.
- **Smoke scripts:** `scripts/ody-635/smoke-queries.sh` (expect 218 PASS; uses `curl -g`), `scripts/ody-700/smoke-regenerate-slug.sh`, `scripts/strapi-v5-delete-204/smoke-delete-204.sh`.
- **Response shape:** every Strapi request sends `Strapi-Response-Format: v4` (`STRAPI_RESPONSE_FORMAT_HEADER`, `frontend/lib/utils.ts:84`). Responses keep `{ data: { id, documentId, attributes } }`, and `flattenAttributes` keeps the top-level `documentId`. `fetchAPI` adds the header. Raw `fetch()` calls and `frontend/scripts/migrate-*.ts` spread it. Guard: `frontend/testing/lib/strapi-response-format-guard.test.ts`.
- **The header changes the shape only.** Numeric single-entry URLs still return 404, unknown keys still return 400, and core DELETE returns 204 with an empty body, even for a missing documentId. Read DELETE responses with `readJsonOrNull` (`frontend/lib/strapi-response.ts`, kept out of `lib/utils.ts` because 43 test files mock utils wholesale). Tests use `makeEmptyResponse(204)`.
- **`id` vs `documentId`** (ODY-600 Decision 1, ODY-601, detailed in `data-fetching.md:210-227`). Use the numeric `id` for filters, comparisons, cache-tag keys, the session, PostHog and lock-route bodies. Use `documentId` for single-entry URLs (`strapiEntryUrl`, `resolveDocumentId`) and relation writes (`resolveDocumentIds`, `entity.documentId`). Exported Server Actions never trust a `documentId` sent by the client. Ids don't change across the v5 boot. The session `documentId` is optional, because old JWTs don't have it. A re-run migration regenerates the documentIds, so restart the frontend afterwards to clear its in-process lookup cache. Guard: `frontend/testing/lib/strapi-entry-url-guard.test.ts`.
- **Lock routes** `/lessons/:id/lock*` accept a numeric id or a documentId since ODY-606. `lesson-lock.ts` still sends numeric ids.
- **DB:** v5 renamed the join tables (`*_links` → `*_lnk`, `*_components` → `*_cmps`, `files_related_morphs` → `files_related_mph`). Index names keep the old names, and the migration is one-way. `scripts/ody-633/01`/`02` use the v4 names on purpose. `03` still uses v4 names until playbook 2.2. v5 drops the DB unique index on uid/slug fields, so two concurrent creates can race.
- **Config shapes:** S3 credentials only go in `s3Options.credentials`, and only when both keys are set (`backend/config/plugins.ts`). CSP directives must be written out in full, including `'self'` (`backend/config/middlewares.ts`). `webhooks.populateRelations` is gone. REST `defaultLimit` is 25 (`backend/config/api.ts`), so a raw fetch without pagination silently caps at 25 rows (ODY-720).
- **Tooling:** `strapi develop` always runs typegen, so commit `backend/types/generated/`. `backend/.prettierrc.json` is required. The lockfile can't be upgraded in place from v4: regenerate it fresh. The 5.56.0 pins are intentional. Only bump `ckeditor5` together with `@_sh/strapi-plugin-ckeditor`.
- **`publicationState`:** the frontend never sends it (0 hits in `frontend/lib`). With D&P off, the v5 `status` query param doesn't apply either. A `status` filter here always means the droplet/voyage domain enum.
