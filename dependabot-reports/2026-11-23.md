## Notes

- Regenerate backend lockfiles with npm 10 (`npx npm@10.7.0 install --package-lock-only`), the npm in CI's Node 20.14. npm 11 (Node 24) leaves out the optional peer entries `@strapi/strapi/node_modules/yaml` and `@strapi/design-system/node_modules/date-fns`, so CI's `npm ci` fails with `Missing: yaml@2.9.1` / `date-fns@4.4.0` even though `npm ci` passes locally. That is what failed #1438 first time round, and it is the same error Dependabot's own PRs show. 8846934c8 (#1431) and 8f4d2ac31 (#1427) add the entries; both pass `npm ci` under npm 10.7 and npm 11.
- How the fixes land: each fix branch goes in as a PR into its Dependabot PR's branch (Jaylen's call), so the Dependabot PR turns green and is merged as usual. No `@dependabot rebase` on those PRs afterwards: it would drop the fix commits. Don't run `dependabot-open-prs.sh --close`, since the cards still say "Supersedes" and it would close the PRs being fixed.
- PRs into `dependabot/` branches run only `check-branches`; build, test and Prettier run on the Dependabot PR once the fix merges into its branch.
- #1426: driver.js 1.14 drops `"over"` from `Side` and centres element-less steps itself, so the two tour intro steps drop `side: "over"` (2 lines, users see no change). 1.14 calls `new DOMRect(...)`, which jsdom lacks; the tour test adds an 8-line stand-in in `beforeAll`, assertions unchanged.
- #1431: plain lockfile regeneration (`Missing: yaml@2.9.1`); lock pinned to 3.1170.0 to match the PR. No code or test changes.
- #1427: lockfile regeneration (`Missing: date-fns@4.4.0`, `yaml@2.9.1`). All 24 Strapi core packages on 5.62.0, design system 2.2.4 → 2.3.1, `stream-chain` 2 → 4 (Strapi data transfer only), one ckeditor5 (48.4.0). No test or code changes.
- #1431 and #1427 both rewrite `backend/package-lock.json`; whichever merges second needs its lockfile regenerated.
- #1422: the regenerated lockfile fixes `npm ci` and backend tests and build pass, but `ci-local.sh` fails `Expected one ckeditor5, found: 48.4.0, 49.1.0`, and the built admin bundle contains both CKEditor version guards. `docs/agent/testing-and-deployment.md` already says to bump ckeditor5 only with the plugin.
