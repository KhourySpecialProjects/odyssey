## Problem

`@ckeditor/strapi-plugin-ckeditor@0.0.11` is v4-only (peer `@strapi/strapi ^4.4.0`, CKEditor 5 41.4.2), and Strapi v5 won't boot while it is installed. Five attributes reference its custom field `plugin::ckeditor.CKEditor` (registered as type `richtext`, `server/register.js:4-8`). Their stored HTML has to survive the move, open in the v5 admin, and render the same on the frontend. The other v4 plugins also need v5 versions or a decision: documentation with a stale override, cloud, i18n, and the aws-s3 upload provider.

## Design Decisions

1. **No data migration by default.** The values are HTML in `text` columns. Changing the field id or preset changes `schema.json` only. A migration (T1.5) is written only if T1.4 or T1.6 finds a v5-specific regression that a data rewrite fixes better than a preset change.
2. **The v5 presets match the v4 presets feature for feature** (Configurator.js lists above), named `light`/`rich`. Official 1.1.2 already ships identical hard-coded `light`/`rich` lists (verified by diff; it only adds a usage-telemetry plugin and an opt-in `openInNewTab` link decorator) and can't be customized. The fork needs both presets written out with `setPluginConfig`. Don't add GeneralHtmlSupport by default: v4 doesn't preserve `hljs`/`<li><p>` either (Open Question 7). **Don't add features beyond v4's:** the frontend has no CKEditor CSS (`.ck-content`, `image-style-*`, `marker-*`, `text-*` are unstyled) and sanitizes with DOMPurify defaults, which strip `<oembed>` and `<iframe>`.
3. **Plugin choice is Open Question 2.** It turns out the official 1.x line does load from the CDN and need a licence key, so the fallback case has happened. The recommendation is the fork `@_sh/strapi-plugin-ckeditor` (see "v5 research results").
4. **Fingerprints, not eyeballing.** Every check uses per-column count, `sum(length)`, the id fingerprint `md5(string_agg(id || ':' || coalesce(col,'<null>'), ',' ORDER BY id))`, and an id-free fingerprint (`ORDER BY md5(...)`), because v5's own migration may re-key rows (unverified). Follow ODY-633's SQL style: `\set ON_ERROR_STOP on`, `\echo` headers, a read-only file. Output goes outside the repo.
5. **Scratch DBs.**
   - `ody598` is cloned from `ody633` and used only for v5 boots of ODY-598 code. The boot script refuses v4 code.
   - `ody598_v4rt` is a second clone of `ody633`, used only for the v4 admin round-trip baseline (T0.5b). It can be dropped after Phase 1.
   - `ody633` itself is never written by this ticket.
6. **Real content stays in `~/ody-598/`**: baseline SQL output, rendered HTML, screenshots, sample ids and round-trip diffs. The repo gets only aggregate counts.

## Constraints Discovered

- CSP (`config/middlewares.ts:3-27`) has `connect-src` = `'self' https:`, `img-src`/`media-src` = `'self' data: blob: market-assets.strapi.io AWS_CDN_URL`, and no `script-src`. **Verified:** Strapi 5 merges CSP directives with its defaults position by position, not by appending. Any directive we set must be written out in full, including `'self'`. There is no `odyssey-dev-bucket…amazonaws.com` host either; the admin preview of dev-bucket images may already be blocked on v4. Note it, don't fix it.
- `config/plugins.ts:46-49` puts `accessKeyId`/`secretAccessKey` directly in `s3Options`. v5 wants `s3Options.credentials` (verified; the old shape still works with a deprecation warning).
- `backend/package.json` engines say node `>=18.0.0 <=20.x.x`. Strapi 5.56.0 needs `>=20.0.0 <=26.x.x`, and so does the fork. That belongs to ODY-597/ODY-604, but Node 18 won't work for any ODY-598 boot.
- `strapi ts:generate-types` fails here because of the root Prettier ESM plugin, so expect to hand-edit **both** generated `.d.ts` files.
- Booting writes churn into the 23 tracked `src/api/*/documentation/1.0.0/*.json` files. Revert it unless the documentation decision says otherwise.
- The Docker `strapi` and `frontend` containers are stopped (checked 2026-10-01). Keep them stopped.

## Edge Cases

- Empty or NULL values: `overview` is NULL on 92 of 133 rows. A few generic and question rows are the empty string. Fingerprints use `coalesce`, and samples include one empty overview.
- The one overview with a code block, under the `light` preset (no CodeBlock): v4 already strips it if an author saves it. Record it, and see Open Question 7.
- Inline math (`data-type="inlineMath"`, plus 2 rows with `\(` or `$$`): the lesson and presentation renderers regex-replace `$…$`/`$$…$$` in the raw HTML and render with KaTeX. Any `$` in text is affected, so pick one math sample and one sample with a literal `$` if one exists.
- `<oembed>` (1 generic row): no frontend code converts it, and DOMPurify defaults strip it, so it renders nothing today. Check that it still renders nothing (and doesn't break the block) after.
- Highlights and notes: **confirmed** to depend on rendered text. Offsets are `TreeWalker(SHOW_TEXT)` character counts over the lesson container after DOMPurify, KaTeX, hljs and the line-number gutter (`generic-block-renderer.tsx:296-372, 451-480`). Any text-node change (whitespace, entities, wrappers) shifts saved highlights. That's why AC2(d) requires an identical `innerText`.
- **Opening `/draft/d/[slug]` writes:** the v1 draft lesson editor re-PUTs the whole block array after mount (`components/draft/lesson/lesson-renderer.tsx:205-211`), and editing the overview through its TipTap input (Document, Paragraph, Text, Link only) saves back only `<p>`/`<a>`. Never visit `/draft` routes during T0.5 or T1.6 captures.
- `required` is kept on the generic, expandable and question fields in both the interim and the final state.

**Recommendation for Open Question 2: the fork.** No licence account, no monthly cap that can make the admin read-only, no third-party CDN or telemetry, and no key in git. Its cost: the field id changes in the 5 schemas (T1.2 rewrites those lines anyway after ODY-597), the presets are ours to keep up, and CKEditor 48 serializes tables differently on save. 13 generic rows and 1 question row have tables, and the T1.4 round-trip check will catch the change.

**Preset spec (fork only):** `light` and `rich`, using the 0.0.11 `Configurator.js` plugin and toolbar lists (lines 30-93 and 166-334), including `fontSize` 9-35, the `fontFamily` list, `image.resizeUnit: "%"` and `list.properties`. Add nothing beyond v4, and no GeneralHtmlSupport (Open Question 7).

**Documentation plugin v5 (5.56.0)** feeds Open Question 3:

- The Strapi docs warn that it "is not actively maintained and may not work with Strapi 5".
- **The `public/` override never worked, in v4 or v5.** On every request the plugin fills its own bundled `index.html`/`login.html` templates and writes them into `src/extensions/documentation/public/`. The tracked files are just generated output.
- **v5 no longer writes the 23 per-API `src/api/*/documentation/1.0.0/*.json` files.** They become dead files.
- **Prod risk:** v5 generates `full_documentation.json` only when `NODE_ENV !== 'production'` (v4 did it on every boot), and in production it reads from `dist/`. Since we gitignore that file, **`/documentation` will have no spec on prod** unless the generated file is committed (5.9 MB) or the plugin is dropped. The intended workflow is "generate in dev, commit".
- The `config/plugins.ts` config (`openapi`, `info`, `x-strapi-config.plugins`/`path`, `servers`, `security`) is still read. `src/extensions/documentation/config/settings.json` is not.
- `/documentation` gets its own CSP sources (`cdn.jsdelivr.net`) automatically.

**S3 target config (`@strapi/provider-upload-aws-s3` 5.56.0):**

- Move `accessKeyId`/`secretAccessKey` into `s3Options.credentials: { accessKeyId, secretAccessKey }`. The upgrade-tool codemod `s3-keys-wrapped-in-credentials` should do this in ODY-597, because our `plugins.ts` is an arrow function returning an object literal, which is the shape it matches. The old shape still works but logs a deprecation warning.
- Keep `baseUrl`, `rootPath`, `region`, `endpoint`, `params.Bucket` and `actionOptions` as they are. They're all still supported. `params` is now required, and we already have it.
- **ACL:** we set no `ACL` key, so v5 sends `public-read`, the same as v4. No change.
- No new env vars. Existing CSP `img-src`/`media-src` already list `AWS_CDN_URL`, in full.

**`@strapi/plugin-cloud` 5.56.0:** an admin page with deploy-to-Strapi-Cloud instructions and no server code. Not needed when self-hosting on ECS. Recommend removing it (Open Question 4).

**i18n:** the upgrade codemod `dependency-remove-strapi-plugin-i18n` removes it, so it belongs to ODY-597. There is no stable `@strapi/plugin-i18n` 5.x release.
