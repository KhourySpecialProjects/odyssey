## Problem

Every Mentor feature (the ODY-887 sidebar and the ODY-888 quiz hints) goes through one streaming route. That route owns:

- auth and view access;
- building the context from ids only;
- the cost check before the model call and the usage row after it;
- the "no answers reach the model" rule;
- streaming text to the browser and stopping when the student stops.

The app has no streaming route yet, so the transport has to be proven on dev, behind the load balancer, before the UI depends on it.

## Acceptance Criteria

From the ticket:

- [ ] **The answer never reaches the model.** Route tests send quiz-hint requests for Classic and BlockNote lessons. They assert that the params sent to the model contain no correct-answer field and no text that marks the right option.
- [ ] **Errors:** 401 when signed out. 403 for a droplet the user can't view, or a draft. 400 for an unsupported question type. 429 past the daily limit. 503 with a clear message past the cap, when Mentor is switched off, or outside the pilot.
- [ ] **Stop:** aborting stops the model stream, and only the tokens actually used are recorded.
- [ ] **Ids only:** lesson text or answers sent by the browser are ignored.
- [ ] An answer streams token by token on dev, not all at once at the end.

Inferred (please approve):

- [ ] Every 200 response is a stream that ends with exactly one `done` or `error` event. Every failure before the model connects is an HTTP status with a JSON body (D7).
- [ ] No usage check, usage row or model call happens for a request refused with 401, 400, 403 or 404.
- [ ] A refusal (`stop_reason: "refusal"`) ends with an `error` event. A `max_tokens` stop ends with `done` and `truncated: true`. Both are recorded.
- [ ] The lesson page and the route decide "can open this lesson" with the same function, and the page 404s a lesson opened under a droplet it doesn't belong to.
- [ ] A response isn't gzipped and isn't buffered by `next start`. It survives a gap of more than 60 seconds with no text.

## What the codebase says (verified unless marked)

**Auth and view access today**

- `app/(droplets)/d/[slug]/[lessonSlug]/page.tsx:41-65` checks only that the user is signed in and that the droplet and lesson exist by slug.
  - It checks no `status`, no `isHidden`, and not that the lesson belongs to the droplet. Lesson slugs are globally unique, so `/d/<any droplet>/<any lesson>` renders.
  - `generateMetadata` (27-35) reads only the lesson.
- The draft editor's **Preview** links to `/d/<draft slug>/<lesson>` (`components/draft/sidebar.tsx:828-834`). Authors and reviewers preview drafts through the learner route, so the page can't become "published only".
- `requireRole([])` (`lib/auth/require-role.ts:36-98`) reads the session, re-reads the user from Strapi, and returns `{ id, email, roles }`. It returns `"unauthenticated"` on any error, Strapi failures included.
- `session.user.id` is the authorized-user id, but it can be missing on older tokens.

**Droplet status**

- `DropletStatus` is `"draft" | "edit" | "published"`. `edit` is legacy:
  - No frontend code sets it. Only `backend/.../droplet/lifecycles.ts:62-63` reacts to it, by sending a Slack message.
  - Review uses `inReview` with `status: "draft"`.
  - Editing a published droplet makes a separate `[EDIT]` draft row (`lib/requests/droplet.ts:919-931`), so the live droplet stays `published`.
  - **A droplet in `edit` is not live; treat it as not published.**
- Listings treat "visible to students" as `status === "published" && isHidden === false`; see the explore page (`app/(general)/explore/page.tsx:70-74`).
- A lesson can be in several droplets: the relation is manyToMany, and lessons have no status of their own.

**Quiz answers and reads**

- Quiz answers already reach the browser: `components/droplets/lessons/quiz-question.tsx:50-52` grades on the client.
- Read functions in `lib/requests/*.ts` are `"use server"` exports, so they're public endpoints. A read that returns answers must live outside them, like `lib/auth/review-freeze.ts` and `lib/overview-scan/scan.ts`. Those use `import "server-only"`, which `next/jest` maps to an empty module (`next/dist/build/jest/jest.js:171-172`).
- `fetchDropletSnapshot` (`lib/ai-review/droplet-snapshot.ts:40-76`) and `SCAN_DROPLET_QUERY` (`lib/overview-scan/scan.ts:19-44`) populate lessons with `LESSON_BLOCKS_POPULATE` inside a droplet read. `objectives()` (`droplet-snapshot.ts:28-29`) maps learning objectives to strings.
- Publishing revalidates `CACHE_TAGS.droplets` and `CACHE_TAGS.lesson` (`lib/revalidate-publish.ts:7-8`). The page reads the lesson with the `lesson` tag for 900 s (`lib/requests/lesson.ts:65-70`).

**Calling Strapi's custom routes**

- `lib/ai-review/run-routes.ts:74-101` is the pattern for custom Strapi routes: raw `fetch` with the service token, `STRAPI_RESPONSE_FORMAT_HEADER`, `cache: "no-store"`, a `{ data }` body that isn't flattened, and status 0 on a network failure.
- AI scoring records `input + cache write + cache read` as its input tokens (`lib/ai-review/score-run.ts:137-144`).

**Transport**

- Both ECS images run `npm start`, which is `next start` (`frontend/ecs.dev.Dockerfile`, `ecs.prod.Dockerfile`). There's no standalone output and no nginx.
- Next compresses responses unless `compress: false` (`node_modules/next/dist/server/lib/router-server.js:108-110`). The bundled `compression` skips any response whose `Cache-Control` holds `no-transform` (`next/dist/compiled/compression/index.js`, `shouldTransform`). `text/event-stream` would otherwise be compressed, and gzip buffers. **`no-transform` is required.**
- `middleware.ts:41-52` doesn't match `/api`, so the route checks auth itself. The CSP `connect-src 'self'` covers a same-origin fetch.
- Next 15.5.26 aborts a route handler's `request.signal` when the response closes early (`next/dist/server/web/spec-extension/adapters/next-request.js:56-63`).
- **Unverified:** the ALB idle timeout. `terraform/` isn't in this checkout. AWS's default is 60 s.

**The SDK** (0.137.0, checked against `node_modules/@anthropic-ai/sdk/src`)

- `messages.stream(body, { signal })` returns a `MessageStream`, and the signal aborts its controller (`lib/MessageStream.ts:226-232`).
- `withResponse()` resolves when the response connects (141-160).
- `'text'` fires only for `text_delta` (521-525). Thinking fires `'thinking'` (539-543). `'streamEvent'` carries each raw event (514-515).
- On abort:
  - it emits `'abort'` and not `'error'`;
  - `done()` and `finalMessage()` reject with `APIUserAbortError` (432-437, 469-477);
  - `'finalMessage'` never fires.
- The async iterator drops an error that arrives while the loop body is running (772-797).
- A mid-stream SSE `error` is a plain `APIError` with `status` undefined (`core/streaming.ts:76-79`).
- `message_delta` usage overwrites `output_tokens`, and also input and cache fields when they're non-null (641-673).
- `StopReason` includes `refusal` and `max_tokens`. Pings are dropped inside the SDK.
- `MessageCreateParamsNonStreaming` passes to `stream()` with no type error.
- The client is built as `new Anthropic()` (reads `ANTHROPIC_API_KEY`), as in `lib/requests/ai-scoring.ts:116` and `scripts/ai-review/lib/plan.ts:146`.

## [CONTRACT] ODY-886 Mentor route (for ODY-887 and ODY-888)

**On develop: not yet.** Build against `testing/mocks/mentorEventsMock.ts` (PR 1) until it is.

**Request:** `POST /api/mentor`, `Content-Type: application/json`. The browser's same-origin `fetch` sends the session cookie. To stop an answer, abort the fetch.

```ts
// MentorRequest = MentorInput & { dropletId: number; lessonId: number }
{ kind: "lesson",    dropletId, lessonId, message: string,   history?: MentorTurn[] }
{ kind: "explain",   dropletId, lessonId, selection: string, history?: MentorTurn[] }
{ kind: "quiz-hint", dropletId, lessonId, questionId: number | string, answerIds: (number | string)[] }
```

- `dropletId` and `lessonId` are positive integer numeric `id`s, not `documentId`.
- `questionId` and the option ids are the ones the rendered quiz block uses. Digit strings are accepted, as `quiz-question.tsx` sends them.
- Text is trimmed:
  - `message` is 1–1,000 characters;
  - `selection` is 1–300;
  - `answerIds` holds 1–10 ids, but a hint needs exactly one wrong pick on a single-answer question with 3 or more options. Anything else is `cannot_answer`.
- Unknown keys are dropped. The server never reads lesson text or answers from the body.

**`history` (the sidebar only; hints take none):**

- Oldest first, alternating `{ role: "student" | "mentor", text }`. It starts with `"student"`, ends with `"mentor"`, and holds at most 6 turns: the last 3 exchanges, so drop the oldest whole exchange.
- A student turn is up to 1,000 characters. An earlier explain turn is stored as its selected text.
- A Mentor turn is the text from that answer's `text` events, clipped to 2,000 characters (`MENTOR_REPLY_MAX`). Keep answers that ended with `done`, including `truncated`. Leave out an exchange whose answer ended with `error`.
- A history that breaks these rules is a 400.

**Before streaming:** each of these is a JSON body `{ error, message, retryAt? }`. They're listed in the order they're checked. Show `message`; don't hard-code text. The strings are proposed here and final in `app/api/mentor/route.ts`.

| Status | `error`                    | When                                                                                                        |
| ------ | -------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 401    | `unauthenticated`          | Signed out ("Sign in to use Mentor.")                                                                       |
| 413    | `too_large`                | Body over 64 KB                                                                                             |
| 400    | `invalid_request`          | Not JSON, or it fails the schema                                                                            |
| 404    | `not_found`                | No such droplet, or the lesson isn't in it                                                                  |
| 403    | `forbidden`                | The droplet isn't published (draft or edit) or is hidden ("Mentor is only available on published lessons.") |
| 400    | `cannot_answer`            | The selection isn't usable (not in the lesson, or in a quiz), or the hint question or pick isn't supported  |
| 429    | `busy`                     | 2 answers already in flight for this user (if D16 is approved)                                              |
| 429    | `daily_limit`              | ODY-884's message, `retryAt` (next midnight Eastern), `Retry-After` header                                  |
| 503    | `monthly_cap`              | ODY-884's message, `retryAt` (next 1st), `Retry-After`                                                      |
| 503    | `disabled`, `not_in_pilot` | ODY-884's message, `retryAt: null`                                                                          |
| 503    | `unavailable`              | The usage check itself failed (fail closed)                                                                 |
| 502    | `model_unavailable`        | Claude failed before the answer started                                                                     |
| 500    | `internal`                 | Anything else                                                                                               |

**200:** `text/event-stream`. Named events with JSON `data`, plus `: ping` comments every 15 s that the reader ignores.

```
event: text
data: {"text":"An index speeds up "}

event: done
data: {"citations":[{"ref":"p3","anchor":{…},"blockIndex":4,"label":"An index speeds up reads…"}],"truncated":false}

event: error
data: {"code":"refused","message":"…"}
```

- `text` is a piece of the answer, in order, as the model writes it. It may hold `[p3]` refs; render a ref that isn't in `citations` as plain text.
- `done` carries `citations`, which is `citationsFor(context, answer)` (ODY-882's `Citation[]`, in the order cited). `truncated: true` means the answer hit the token limit: show what arrived, with a "cut off" note.
- `error`:
  - `code: "refused"`: the model declined; partial text may have arrived.
  - `code: "failed"`: the API broke mid-answer, the 90-second ceiling was hit, or there was no text.
  - After an error, discard the text shown for this answer and show `message`.
- Every 200 ends with exactly one `done` or `error`, and then the server closes the stream.
- `readMentorEvents` stops at that event. It throws `MentorStreamError` if the stream ends without one or sends a frame that isn't JSON, and the fetch's `AbortError` when the student stops: treat any other throw as `failed`.
- A `[pN]` ref can be split across two `text` events, so find refs in the whole answer so far.
- Check `res.ok` and `res.body` before reading. A 502 or 504 from the load balancer, or Next's own 500, isn't JSON.
- To stop an answer, abort the fetch.

## The route's sequence

1. `requireRole([])`. Not ok gives 401.
2. A `content-length` over 64 KB gives 413. Then `request.json()` and `mentorRequestSchema.safeParse`; either failing gives 400 `invalid_request`.
3. `getMentorSource(dropletId, lessonId)`. No droplet, or no lesson, gives 404.
4. `lessonAccess(droplet, lessonId)`. Not ok gives 404; `!mentor` gives 403.
5. `buildLessonContext(lesson, droplet)`, then `resolveMentorAsk(lesson, context, input)`. An error gives 400 `cannot_answer`, and the code is logged.
6. `tryStartAnswer(userId)` (D16). Null gives 429 `busy`. From here, every exit releases it.
7. `checkMentorUsage(userId)`. Null gives 503 `unavailable`. A refusal gives 429 for `daily_limit`, 503 otherwise, with `Retry-After` when `retryAt` is set.
8. `streamMentorAnswer({ client, params: buildMentorRequest(context, ask), context, signal: request.signal, onFinish })`. Null (failed before connect) gives 502, with no row. Otherwise the SSE `Response`.
9. `onFinish(tokens)`. If there are tokens, `recordMentorUsage({ userId, kind, model, ...tokens })`; a failure is logged. Then release the burst slot.

Steps 1–7 never call the model. Steps 1–5 never call ODY-884. The whole handler sits in `try`/`catch`, which gives 500 `internal` and releases the slot.

## Edge cases

- **Overshoot.** Concurrent answers all pass ODY-884's read-only check. D16 bounds that to 2 per user per task, times the number of ECS tasks.
- **Strapi down at auth.** `requireRole` reports Strapi being down as `unauthenticated`, so a Strapi outage reads as 401, not 503. That's existing behaviour; noted for the UI.
- **Short lessons.** A prompt prefix under 512 tokens (the minimum on both Haiku 5.5 and Sonnet 5.5) doesn't cache. This is silent and harmless.
- **Long answers in history.** An answer over 2,000 characters would make the next request a 400 unless the browser clips it. The contract says it clips.
- **Drafts by URL.** Students can still open drafts and hidden droplets by URL (ODY-660). Mentor gives 403 there, and the sidebar hides when `mentor` is false.
- **A failed record.** It's logged and the cap undercounts by one answer. There's no retry.
- **The old lesson after a publish.** During the 900-second cache, Mentor and the page both show the pre-publish lesson. Publishing revalidates both tags, so this only happens if revalidation fails.
