**Correction to the ticket:** these three custom-lesson calls are **not** inside `strapi.db.transaction`.

- Only `acquireLock`'s read-then-write runs in the transaction, and it already uses `strapi.db.query` (the Query Engine).
- The Query Engine isn't deprecated, so `acquireLock` keeps it.
- The ticket's "all or nothing" criterion applies to `acquireLock`, and Task 2 tests it.

## Rules

- **Before hooks (only the numeric id is known):** `strapi.documents(uid).findFirst({ filters: { id: event.params.where.id }, fields, populate })`. That's one query, and no documentId is needed.
- **After hooks (`result` has a `documentId`):** `strapi.documents(uid).findOne({ documentId: result.documentId, fields, populate })`.
- **custom-lesson:**
  - **Look the lesson up from `:id`** with a new `findLessonWithLock(ref)`, which uses `strapi.documents("api::lesson.lesson").findFirst(...)`:
    - `:id` all digits → `filters: { id: Number(ref) }`;
    - `:id` matches `/^[A-Za-z0-9]+$/` → `filters: { documentId: ref }`;
    - anything else → 404.
    - Fetch `fields: ["lockedAt"]` and `populate: { lockedBy: { fields: ["id", "firstName", "lastName"] } }`. The result includes `documentId`.
  - **Release and heartbeat** write with `strapi.documents(uid).update({ documentId: lesson.documentId, data })`.
  - **Response shapes, status codes and messages stay exactly the same.** `frontend/lib/requests/lesson-lock.ts` and its tests depend on them. Check that file and match it.
  - **`:id` accepts a numeric id or a documentId**, so the frontend can switch to documentIds later. The frontend keeps sending numeric ids in this PR.
  - **`acquireLock`** keeps its Query Engine compare-and-swap inside `strapi.db.transaction`. Give it the same `:id` handling: if `:id` is a documentId, resolve it to the numeric id with `db.query(...).findOne({ where: { documentId }, select: ["id"] })` inside the transaction, then keep the existing logic.
- **Behavior differences to check, and record in a comment where they matter:**
  - `documents.update` runs the entity validator and the lesson `beforeUpdate` hook. The data has no `blocks`/`blocksV2` and no `regenerateSlug`, so the hook does nothing.
  - `documents.update` with `lockedBy: null` clears the relation.
  - `findFirst` returns `null` when nothing matches, the same as before.
- **No `strapi.entityService` left in `backend/src`.** Add a tiny guard test that greps `backend/src` and fails on any `entityService` usage.

## Task 2: custom-lesson controller and lock-route tests

Convert the controller as above, then add `backend/tests/api/lesson-lock.test.js`. It uses REST through supertest with the ODY-599 API-token helper, plus fixtures (a lesson and two authorized users).

- **acquire:**
  - 200 and the lock is stored;
  - 409, with `lockedBy`/`lockedAt`, when another user holds a fresh lock;
  - 200 when the other user's lock is stale (set `lockedAt` more than 60 s ago through the Query Engine);
  - 200 when the same user re-acquires;
  - 400 for a missing or invalid `userId`;
  - 404 for an unknown lesson.
- **release:**
  - 403 when a non-holder releases a fresh lock;
  - 200 for the holder, and the lock is cleared;
  - 200 for a non-holder when the lock is stale;
  - 400 without `userId`;
  - 404 for an unknown lesson.
- **heartbeat:**
  - 403 for a non-holder or when unlocked;
  - 200 for the holder, and `lockedAt` moves forward;
  - 404 for an unknown lesson.
- **lock-status:** locked and fresh, stale (reported as unlocked), never locked, and 404.
- **`:id` forms:** each route works with the numeric id **and** the lesson's documentId. An id like `../x` gets 404.
- **All or nothing** (the ticket's acceptance criterion):
  - Spy on the lesson Query Engine `update` so it runs the real update and then throws.
  - Call acquire and expect 500 "Failed to acquire lock".
  - Then read the lesson and check that `lockedBy`/`lockedAt` are unchanged, i.e. the transaction rolled back.
  - Restore the spy afterwards.
- **Lifecycle side effects:** release and heartbeat go through `documents.update`, which runs the lesson lifecycle. Assert that `slug` and content are unchanged after a heartbeat.
