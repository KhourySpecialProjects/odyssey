# ODY-882: Mentor: lesson context and citations for both lesson formats

## Status (2026-11-04)

Tasks 1–8 are built on `feature/ody-882-mentor-lesson-context-and-citations-for-both-lesson-formats` (uncommitted, from develop `7fd922b1`). Verified with the Mentor unit tests, the full frontend suite, and a scratch run over all 360 lessons in the local database (86 BlockNote, 274 Classic), rendered through the real `LessonRenderer` in Jest.

Changed from this plan during the build:

- **Classic anchors** are offsets into Mentor's own Classic text, built block by block: quizzes as their question and option text only, open-ended questions as the question only, videos as nothing. Not `classicLessonHtml`'s text, whose `(correct)` and `Expected answer: …` would make every later offset reveal an answer's length. With answers out, prefix and suffix are no longer clamped to a component. `lessonAnchorContent` returns this text.
- **Budget:** the passage that crosses the budget is cut to fit (ending in `…`, with an open code fence closed) when at least 200 characters fit, not only the first passage.
- **`locateSelection`** returns `[]` when the text is only in passages without a ref, and `null` only when it isn't in the lesson.
- **Quiz option text** goes through `htmlToMarkdown`, as the page draws options as HTML. Blank lines inside a passage are dropped outside code fences, so a blank line always separates passages.

After an independent review (all thirteen findings checked against the code, then fixed):

- **Interface additions:** `Passage.blockIndex` and `Citation.blockIndex` (the block's index in `displayBlocksOf(lesson)`, the `i` of the page's `displayBlocks.map((b, i) => …)`), and `LessonContext.trimmed`. `omitted` counts passages left out entirely.
- **Budget:** a cut passage always gets a note, `[Trimmed: the rest of this passage is left out for length.]` when nothing follows it.
- **`citedRefs`** copies `REF_PATTERN`: `matchAll` starts from a shared regex's `lastIndex`.
- **`locateSelection`** returns the refs of every copy of the selected text, in page order.
- **Callouts** come from the page's own `blocksToHtml`, nested lists moved into their items, so nested items and images aren't lost. Mentor no longer uses `review-classic.ts`.
- **Code and sandboxes** are Mentor's own Markdown, built field by field (a notebook's `testCode` is never read), in a fence longer than any backticks in the code. `serialize.ts` is unchanged.
- **Ids two BlockNote blocks share** get no anchor, `findQuizQuestion` gives null for a shared question id, and a ref needs its quote in the passage's own text.
- **Labels** come from the passage's Markdown without its marks; code labels from the code.
- Presentation mode keeps its own copy of the "which blocks" rule (`components/presentation/utils.ts`), outside this ticket.

Where the sections below disagree with this status, the code (`lib/mentor/`, its header comment and `types.ts`) is the contract.

Found on the learner page (for ODY-887): Classic quotes are stored text, and the page rewrites two kinds of text, so 25 of 4,347 text citations in the local data aren't found by plain text search there. `processLatex` turns `$…$` into KaTeX (shell prompts, Swift `$state`, template literals; inside code blocks too, in 6 lessons), and code blocks get a line-number gutter in front of the code. BlockNote citations were all found, 1,175 by `data-block-id`.

## Problem

Mentor (AI Mentor project) needs the lesson as prompt text it can cite, and the sidebar needs to jump to whatever it cites. Lessons come in two formats: BlockNote (`blocksVersion: "v2"`, JSON in `blocksV2`, block ids that last) and Classic (Strapi dynamic zone `blocks`, no lasting ids, so anchors go by quote, ODY-801). The prompt must never contain a quiz's correct answer. ODY-885 (prompt and eval), ODY-886 (streaming route), ODY-887 (sidebar), ODY-888 (Explain my answer) and ODY-889 (Explain on a selection) all build on this module, so its exported interface is a contract between Brady's and Jaylen's tickets.

- [ ] A lesson over the budget is trimmed, and a test covers it.

Inferred (state for approval):

- [ ] The prompt text is identical whichever option is correct (it doesn't depend on the answer at all), and no part of the module's output, anchors included, contains `isCorrect`, `correctAnswer`, `(correct)`, `Expected answer` or the open-ended answer text.
- [ ] The prompt text is built only from the lesson and droplet, never from the message or selection, so the route can cache it (ODY-886).
- [ ] The learner page and this module choose and convert blocks with one shared function, so quiz ids can't drift.
- [ ] `citationsFor` turns `[p3]` / `[p3, p5]` in an answer into citations, keeping only passages that were in the prompt.
- [ ] `locateSelection` finds a selection's passage in either format, including BlockNote code blocks and quiz text, ignoring whitespace differences.
- [ ] Client components can import the types and the ref parser, but not the builder (guard test).

## Ticket assumptions that turned out wrong in the code

1. **True/false option ids aren't `blockIndex * 100 + optionIndex`.** Multiple choice is (`convert-blocks.ts:407`). True/false is `blockIndex * 10 + 1` and `+ 2` (`:425`, `:431`). `blockIndex` is the block's raw index in `blocksV2` (`:898`), counting empty paragraphs and every other block, so ids change when a block above is added. A BlockNote question's id is `blockNoteIdToNumber(block.id)`, or the index when the block has no id (`:328`).
2. **The four answer fields become two after conversion.** BlockNote MC and true/false both come out as `droplets.quiz` with `answerOptions[].isCorrect` (`:409`, `:427`, `:432`), and open-ended as `correctAnswer` (`:447`). Going through the conversion (as the page does) means removing those two v1 fields; the tests still cover all four source shapes.
3. **`serialize.ts` puts answers in.** `blockToMarkdown` writes `(correct)` before options (`serialize.ts:187`) and `Expected answer:` for open-ended (`:198`). `classicLessonHtml` (`review-classic.ts:96`, `:107`), the Classic anchor text, has them too. Its passage unit is also a whole v1 block: consecutive BlockNote paragraphs and list items are merged into one generic block, whose numeric id is a hash, not the BlockNote id anchors use. So `lessonToMarkdown` can't be reused for cited passages (see Reuse).
4. **`htmlContent` and `createAnchor` need a browser DOM** (`DOMParser`, `Range`). On the server the matching function is `htmlTextContent` (`lib/anchors/html-text.ts`, kept out of the anchors index on purpose), and anchors are built as plain objects, as `lib/ai-review/findings.ts` does.
5. **"The sidebar finds it with `resolveAnchor`" works for BlockNote only.** A Classic anchor resolves against the review view's text (`classicLessonHtml`), and the learner page draws differently: quizzes, callouts (`blocksToHtml`) and expandables are drawn another way, and an expandable's content isn't in the DOM while it's closed (Radix `Collapsible`). On the learner page a Classic citation has to be found by its quote. In BlockNote lessons, only paragraphs, headings, list items and quotes have `data-block-id` on the learner page. Callouts, tables, code, images and quizzes don't.
6. **ODY-889's note (match against `htmlContent` / `blockNoteContent`) would fail.** `blockNoteContent` has no text for code blocks, quiz questions or images (`content: "none"`), and `htmlContent` can't run on the server. This plan adds `locateSelection` instead. Side findings in AI review's serializer, not fixed here: BlockNote tables reach the model as the raw `<!--TABLE_START-->` JSON (`htmlToMarkdown` drops the comments but keeps the JSON text), and Classic callout lists lose their text (`serialize.ts:173-175` reads only `children[].text`).
7. **`server-only` isn't installed.** Next resolves it internally and Jest maps it. ODY-885's eval runs under `npx tsx`, where `import "server-only"` wouldn't resolve, so the boundary is enforced with a guard test instead.
8. **Answer ids are strings on the client.** `quiz-question.tsx` saves `String(answerOption.id)` and the radio `value` is `String(answer.id)`. ODY-886's Zod schema should coerce `answerIds` to numbers before comparing them with the lookup.

## Contract

### 1. Exported interface

```ts
// frontend/lib/mentor/types.ts — types only; safe to import anywhere, client included
import type { Anchor } from "@/lib/anchors/types";
import type { Block, CustomBlockNoteBlock } from "@/types";

/** The lesson fields Mentor reads. A `Lesson` or an AI-review `SnapshotLesson` fits. */
export type MentorLesson = {
  id: number;
  name: string;
  blocksVersion?: "v1" | "v2" | null;
  blocks?: Block[] | null;
  blocksV2?: CustomBlockNoteBlock[] | null;
};

/** The droplet fields Mentor reads */
export type MentorDroplet = {
  name: string;
  difficulty?: string | null;
  learningObjectives: string[];
};

/** One piece of the lesson, in page order */
export type Passage = {
  /** "p1", "p2"… in page order. Null for content Mentor sees but can't cite: images, video. */
  ref: string | null;
  /** As sent to the model, without the ref */
  markdown: string;
  /** The text a reader sees: for the Sources label and matching a selection. Never an answer. */
  plain: string;
  /** Where it is in the lesson (field "blocks"). Null exactly when ref is null. */
  anchor: Anchor | null;
  /** False when the size budget left it out of `text` */
  inPrompt: boolean;
};

export type LessonContext = {
  lessonId: number;
  format: "blocknote" | "classic";
  /** Droplet and lesson details, then each passage as "[p3] …", trimmed to the budget */
  text: string;
  /** Estimated tokens in `text`, at 4 characters a token */
  tokens: number;
  /** Every passage, including any the budget left out */
  passages: Passage[];
  /** How many passages the budget left out; 0 when the lesson fits */
  omitted: number;
};

/** A cited passage, as the route sends it to the sidebar at the end of an answer */
export type Citation = {
  ref: string;
  anchor: Anchor;
  /** The passage's first words (about 80 characters), for the Sources line */
  label: string;
};

/** A choice question as the learner page shows it, with no answer */
export type MentorQuizQuestion = {
  questionId: number;
  /** The question as Markdown */
  question: string;
  /** In page order, with the ids the page renders. True/false has two. */
  options: { id: number; text: string }[];
};
```

### 2. Prompt text format

````
Droplet: <name>
Difficulty: <difficulty>            (line left out when there's none)
Learning objectives:
- <objective>                       ("- (none listed)" when there are none)
Lesson: <lesson name>

[p1] ## Heading text
[p2] Paragraph as Markdown…
[p3] - First list item
[p4] [Callout, warning] Text…
[p5] [Quiz question] What does a LEFT JOIN keep?
  - All rows from the left table
  - Only matching rows
[Image: entity diagram]             (no ref: can't be cited)
[p6] [Code block, python, runnable]
```python
…
````

[Trimmed: the last 12 passages of this lesson are left out for length.]

```

Passages are separated by a blank line. The prompt for ODY-885 should tell the model to cite as `[p3]` (several as `[p3][p5]` or `[p3, p5]`), and that a `[Trimmed: …]` line means it can't see the end of the lesson.

### 5. Passage rules per v1 block

After `displayBlocksOf(lesson)`:

| v1 block                        | Passages                                                                                                                                                                                      |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `droplets.generic`              | Split `classicBlockHtml(block)`. A `<!--TABLE_START-->` block becomes one passage whose Markdown is the JSON's `markdown` field. Slide, column and empty-paragraph blocks give nothing.              |
| `droplets.expandable` (Classic) | Title passage `[Expandable section] <title>`, then the split content                                                                                                                         |
| `droplets.callout`              | One passage: `[Callout, <type>] ` + `htmlToMarkdown(classicBlockHtml(block))`                                                                                                                 |
| `droplets.quiz`                 | One passage per question: `[Quiz question] <question md>` with one `  - <option>` line per option. No `isCorrect`. `plain` is the question and options.                                       |
| `droplets.open-ended-quiz`      | One passage per question: `[Open-ended question] <question md>`. No `correctAnswer`.                                                                                                          |
| `droplets.code-block`, `droplets.sandpack-block` | One passage: `blockToMarkdown(block)`. `plain` is the code, or the sandpack description.                                                                                       |
| `droplets.video`                | Unreferenced `[Video: <url>]`                                                                                                                                                                 |

The splitter, for generic and expandable HTML:

- Top-level elements each make one piece.
- It descends into `div`, `section` and `article` wrappers that have block-level children.
- Runs of inline nodes are grouped into one piece.
- In a BlockNote lesson, every element with `data-block-id` is its own piece. For an `li`, that's its own text without nested lists or `span[data-block-id]` children, with `- ` or `N. ` and two spaces of indent per level. The splitter then descends into the nested lists and children.
- In a Classic lesson, `data-block-id` is ignored.
- A piece with no visible text is dropped, except an `<img>`, which stays unreferenced as `[Image: alt]`.
```
