# ODY-587: Replace `next lint` with the ESLint CLI and flat config

**Re-executed 2026-09-28 on the correct base (2c63601e)** after a prior run used a stale base. Baseline: `npx next lint` 202 warnings/0 errors (app+components+lib); legacy Next config on `hooks types` added 12 warnings. After: `npm run lint` = 212 warnings, 0 errors. Both parity diffs clean (only ESLint-9 default-option fill-ins and the intentional `no-unused-vars` ignore-pattern option tied to its approved downgrade).

## Problem

Next 16 removes `next lint` and the `eslint` key in `next.config`. The frontend `lint` script is `next lint`, and `next.config.mjs` sets `eslint.ignoreDuringBuilds`. Both have to go before ODY-588 (Next 16 upgrade), which this ticket blocks.

**The ticket assumes the wrong thing about CI.** CI does not run `next lint` today:

- `.github/workflows/prettier.yml` (lint job) runs `npm ci --legacy-peer-deps` and `npm run lint` at the **repo root**.
- Root `lint` is `cd frontend && eslint app components --ext .js,.ts,.tsx`. It runs **root ESLint 9.39.1** with the **root `eslint.config.mjs`**: `@eslint/js` recommended, `typescript-eslint` recommended and `eslint-plugin-react`, with no Next, react-hooks or jsx-a11y rules. It covers `app/` and `components/`, but not `lib/`.
- `/ci` (`.claude/commands/ci.md`) and `scripts/ci-local.sh` also call root `npm run lint`.
- `frontend/.eslintrc.json` (next/core-web-vitals + next/typescript + overrides) only takes effect when someone runs `cd frontend && npm run lint` by hand. Frontend ESLint is 8.57.1, pulled in as a peer of `eslint-config-next@15.5.9`.

So there are two rule sets today. Removing `next lint` would not break CI, but it would break the only way to run the Next rule set. This plan makes the Next rule set the one source of truth, and has CI enforce it.

**Rule-set gap (measured 2026-09-28, `--print-config` on `app/layout.tsx` and `lib/utils.ts`):** the Next config alone is not a superset of what CI enforces today.

- It is missing **42 core `@eslint/js` recommended rules** that root CI runs as errors, for example `no-fallthrough`, `no-case-declarations`, `no-cond-assign`, `no-unsafe-finally`, `no-unsafe-optional-chaining`, `use-isnan`, `valid-typeof`, `no-debugger`, `no-empty` and `no-useless-catch`.
- **5 rules drop from error to warn** because of the `.eslintrc.json` overrides: `prefer-const`, `@typescript-eslint/no-explicit-any`, `@typescript-eslint/no-unused-vars`, `@typescript-eslint/no-unused-expressions` and `@typescript-eslint/no-wrapper-object-types`.
- It adds 47 rules: react-hooks, jsx-a11y, `@next/next/*`, `react/jsx-key` and others.

With core recommended added, the only new errors across `app components lib hooks types` are 4 `no-case-declarations` in `lib/utils.ts` (lines 638, 651, 660 and 670, in the block-to-markdown `switch`). `prefer-const` also has 4 hits in `lib/`, but it is already `warn`. Under the Next config, `hooks/` (5 files) has 0 problems and `types/` (4 files) has 0 errors and 11 warnings.

Gotcha: frontend ESLint 8 walks up to the root `eslint.config.mjs` and switches to flat mode, so it ignores `.eslintrc.json`. To get the real legacy config, you must set `ESLINT_USE_FLAT_CONFIG=false`.

## Design Decisions

**D1. The frontend config (Next config plus core `@eslint/js` recommended) becomes the single source of truth, and CI enforces it. (Approved 2026-09-28.)**
Root `lint` becomes `npm run lint --prefix frontend`. `/ci` and `ci-local.sh` already call root `npm run lint`, so they need no changes. The CI lint job installs frontend deps instead of root deps.

- `js.configs.recommended` is added so CI keeps the 42 core rules it enforces today. The Next config alone would silently drop them.
- The 5 rules the `.eslintrc.json` overrides set to `warn` stay at `warn`. CI stops blocking on them in `app` and `components`, which is an accepted trade-off. Raising them back is a follow-up.
- CI gains the 47 Next, react-hooks and jsx-a11y rules, plus coverage of `lib`, `hooks` and `types`.
- Alternative (B): keep the root config for CI and migrate only frontend. That leaves two rule sets. Root `lint` would also need `-c ../eslint.config.mjs`. Without it, ESLint picks up the nearest config (the new `frontend/eslint.config.mjs`), which can't resolve `eslint-config-next` in the CI job because frontend deps aren't installed there. It would pass locally and fail in CI. Not recommended.

**D2. Lint `eslint app components lib hooks types`, not `eslint .`. (Deviates from ticket text; approved 2026-09-28.)**
`next lint` covers `app`, `components` and `lib`. `hooks` and `types` are app code, and they are already clean under the new rules, so we add them for free. `eslint .` would pull in about 169 errors in test and config files, which breaks "same rules as before" and keeps AC1 from passing without a large unrelated cleanup. The config still gets the artifact ignores the ticket asks for, so editors and ad-hoc `npx eslint .` skip generated files. Widening to tests, e2e and scripts is a follow-up.

**D3. Use FlatCompat on Next 15.5.** `eslint-config-next@15.5.9` only ships legacy (eslintrc) configs. `@next/eslint-plugin-next` has `flatConfig`, but it doesn't bundle the react, react-hooks, import, jsx-a11y and typescript-eslint pieces. FlatCompat is the path Next 15 documents, and it gives exact parity. ODY-588 replaces the two `compat.extends` entries with native `eslint-config-next/core-web-vitals` and `/typescript` imports once it bumps to v16, and drops `@eslint/eslintrc`.

**D4. Replace `eslint.ignoreDuringBuilds` with `next build --no-lint`.** On Next 15, removing the key alone would make `next build` start linting. That affects CI `build.yml` and the prod Docker build (`ecs.prod.Dockerfile` installs dev deps, and the new config would be copied in). `--no-lint` keeps build behavior exactly as it is today. ODY-588 must remove `--no-lint`, since Next 16 builds don't lint and the flag is gone.

**D5. Keep ESLint 9's unused-directive default ("warn").** It isn't a rule and never fails the run. It may add a few warnings to the count.

**D6. The codemod is a starting point, not the final word.** `@next/codemod@latest` targets Next 16. It may bump `eslint-config-next` to 16, write native flat imports, or set the script to `eslint .`. Reconcile its output to D2–D3: keep `eslint-config-next` at `^15.x` to match `next`.
