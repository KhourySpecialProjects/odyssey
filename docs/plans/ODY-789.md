## Problem

The scan's four network checks (Images, Videos, Links, Datasets) have to visit URLs that creators typed into lessons. The request comes from the Next.js server on ECS, inside Odyssey's AWS network. Without a guard, a lesson link is a server-side request forgery (SSRF): it can reach `169.254.169.254` (instance and task credentials), Strapi and other services on private addresses, or `localhost`. That's true directly, through a redirect, or through a public hostname that resolves to a private address.

Nothing in `frontend/` fetches arbitrary URLs today. There's no `server-only` usage, no `undici` dependency, and no Node `http`/`dns`/`net` code in `lib/`. This is new ground.

## How the code works now (verified on d9cdbfb4; the tasks rely on these facts)

- **Runtime:** `frontend/Dockerfile` is `node:22-alpine`, with Next `^15.5.26` and `@types/node ^20.12.3`. In Node 22:
  - `http.request` accepts `signal`, `lookup` and `agent: false`.
  - `autoSelectFamily` is on by default, so `net` calls `lookup(host, { all: true, … }, cb)`.
  - `net.BlockList` exists.
- **No `undici` in `frontend/package-lock.json`.** Node's global `fetch` takes an undocumented `dispatcher`, but only an `Agent` from the npm `undici` package can supply one. That would be a new dependency, and the npm version has to match Node's bundled copy.

  - Nothing in `frontend/` uses it yet. `lib/auth/review-freeze.ts` is "server only, not `"use server"`" by convention only.
- **`"use server"` makes every export a public POST endpoint** (`docs/agent/server-action-auth.md`). `checkUrls` must not be one: it would be an open proxy and port scanner that skips the scan's auth and rate limit.
- **Jest** (`frontend/jest.config.js`):
  - The default environment is `jsdom`.
  - No test uses `@jest-environment node` yet; this one should, for real `AbortController`, timers and `node:http`.

  - the URL's host;
  - any address the host resolves to;
  - any redirect target.

  That includes:

  - `localhost`, `*.localhost`, `*.local`, `*.internal`, single-label names and trailing-dot forms;

- [ ] **AC4** The address check runs inside the connection's own DNS lookup, so the address that's checked is the address that's connected to (D1). A public name that resolves to `127.0.0.1` is refused.
- [ ] **AC5** Redirects are followed by hand. Every hop is checked again (scheme, host and resolved address). A response that still redirects after 5 redirects returns `unchecked`, `too-many-redirects`.
- [ ] **AC6** Each hop sends HEAD. If HEAD returns 400 or more (except 429), the same hop is retried once with GET. A response body is never read.

- [ ] **AC9** Requests carry only `User-Agent` and `Accept`: no cookies, no `Authorization`, no Strapi or Odyssey tokens, and no credentials from the URL (`user:pass@`). Every request has its own socket (`agent: false`).

## Design Decisions

- **D1. Pin the connection to the checked address by validating inside `lookup`, using Node's `http`/`https.request` (recommended).**

  - **The rebinding problem.** Calling `dns.lookup` and then `fetch(hostname)` resolves the name twice. A rebinding DNS server answers public the first time and `127.0.0.1` the second.
  - **The fix:**
    - Don't pre-resolve at all.
    - Pass `http(s).request({ hostname, lookup: safeLookup(dnsLookup), agent: false, … })`.
    - Node calls `safeLookup` once, for the socket it's about to open. `safeLookup` resolves with `all: true`, refuses if **any** returned address fails `isPublicAddress`, and otherwise hands Node exactly the addresses it checked.
    - There's no second resolution, so there's nothing to rebind.
    - `https` keeps the real hostname for SNI and certificate checks, because `hostname` is still the name.
  - **Callback shape:** `safeLookup` must answer in the shape Node asked for. With `options.all`: `cb(null, LookupAddress[])`. Without it: `cb(null, address, family)`. Node 22 asks for `all: true` because `autoSelectFamily` is on by default.
  - **IP literals:** Node skips `lookup` entirely for a hostname that is already an IP. So the preflight (D3) checks literal hosts before any request. Literals and names together cover every case.
  - **Not `fetch`:** this sidesteps both Next's `fetch` patch and its data cache, and `redirect: "manual"` is implicit (`http.request` never follows redirects).
  - **Alternatives:**
    - **Global `fetch` with an undici `Agent({ connect: { lookup } })` dispatcher.** The same idea, but it needs `undici` as a new dependency. The npm `undici` and Node's bundled one must stay compatible (a version skew breaks `dispatcher`). It goes through Next's patched `fetch` (needs `cache: "no-store"`). And it's harder to stop a body download.
    - **Resolve, check, then connect to the IP with a `Host` header and `servername`.** No new dependency, but it hand-rolls SNI and `checkServerIdentity`, and it's easy to get TLS subtly wrong. D1 gets the same pinning for free.

- **D2. Address classification uses `net.BlockList`, with no new dependency (recommended).**

  - **The function:** `isPublicAddress(ip)` uses `net.isIP` to find the family. Anything that isn't an IP is not public.
  - **IPv4:** public unless it's in `DENY_V4` (D3).
  - **IPv6:**
    - IPv4-mapped (`::ffff:0:0/96`) is judged by the IPv4 rules. Node's `BlockList.check(addr, "ipv6")` matches IPv4 rules for mapped addresses (the Node docs show `::ffff:7b7b:7b7b`).
    - Otherwise, public only if it's inside global unicast `2000::/3` and not in `DENY_V6`. Using an allowlist means NAT64 `64:ff9b::/96`, `::`, `::1`, `fc00::/7`, `fe80::/10`, `fec0::/10`, `ff00::/8` and any future special range are refused without being listed.
    - **Gotcha:** a test pins the mapped behaviour (`::ffff:127.0.0.1` and `::ffff:7f00:1` refused, `::ffff:8.8.8.8` allowed). If `BlockList` doesn't match mapped addresses on the CI Node version, decode the last 32 bits by hand.
  - **Alternative:** hand-rolled bit checks, about 40 more lines with more room for mistakes. Or `ipaddr.js` / `ssrf-req-filter`, which are new dependencies for something Node already ships.

- **D3. Preflight runs on the input URL and on every redirect target.**

  1. **Parse.** `new URL(input)` must succeed, otherwise `invalid-url`. Relative URLs fail here.
  2. **Scheme.** The protocol must be `http:` or `https:`, otherwise `unsupported-scheme`.
  3. **Normalize the host.** Take `url.hostname`, lowercase it, strip `[` `]` and trailing dots.
     - WHATWG `URL` has already normalized decimal, octal and hex IPv4 (`http://2130706433/` → `127.0.0.1`) and compressed IPv6 (`[::ffff:127.0.0.1]` → `[::ffff:7f00:1]`).
     - Always use the normalized host, never the raw input string.
  4. **IP literal.** If the host is an IP, it must pass `isPublicAddress`.
  5. **Name.** Otherwise refuse:

     - an empty host;
     - `localhost` and `*.localhost`;
     - `*.local` and `*.internal` (AWS's `*.compute.internal` and `*.ec2.internal`);
     - names with no dot (`backend`, `strapi`, Docker and ECS service names).

     These name rules are defense in depth. The real control is the resolved-address check (D1).

  - **`DENY_V4`:** `0.0.0.0/8`, `10.0.0.0/8`, `100.64.0.0/10`, `127.0.0.0/8`, `169.254.0.0/16`, `172.16.0.0/12`, `192.0.0.0/24`, `192.0.2.0/24`, `192.88.99.0/24`, `192.168.0.0/16`, `198.18.0.0/15`, `198.51.100.0/24`, `203.0.113.0/24`, `224.0.0.0/4`, `240.0.0.0/4`.
    - `0.0.0.0` matters: it connects to the local host on Linux.
    - `100.64/10` matches the prototype.
  - **`DENY_V6`** (inside `2000::/3`): `2001::/23` (IETF protocol assignments, including Teredo, which embeds IPv4), `2001:db8::/32`, `2002::/16` (6to4, which embeds IPv4) and `3fff::/20` (documentation).
  - **Credentials:** a URL with `user:pass@` isn't refused, but the credentials are never sent (AC9, Task 2's gotcha).
  - **Ports:** any port is allowed. The host must be public, so the internal-network risk is already closed.
  - **The fragment** (`#…`) is never sent.

- **D4. Size comes from `Content-Length` only, and no body is ever read.**

  - HEAD responses have no body.
  - On the GET fallback, the response is destroyed as soon as the headers arrive (`res.destroy()`). A 5 GB "image" costs one header read.
  - `bytes`:
    - a non-negative integer when `Content-Length` parses as one;
    - `null` otherwise, for example on chunked responses.
  - We send no `Accept-Encoding`, so `Content-Length` is the identity size.
  - With `bytes: null`, ODY-793's 2 MB rule passes, as in the prototype. Odyssey's own media on S3 and CloudFront always sends `Content-Length`.
  - **Alternative:** when the header is missing, stream and count up to `maxImageBytes + 1`, then abort. About 15 more lines and up to 2 MB of download per image. Not worth it now (YAGNI). It's easy to add later behind the same `bytes` field.

- **D5. What each response means, grounded in ODY-793's rules.**

  | Response (after the HEAD → GET fallback)          | Result                             | Why                                                                                                            |
  | ------------------------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------- |
  | 2xx                                               | `loaded`                           | Images, Links and Datasets.                                                                                    |
  | 3xx with `Location`, within 5 redirects           | follow it                          | The ticket.                                                                                                    |
  | 3xx without `Location`, or 304                    | `loaded` with that status          | Links: "2xx or 3xx".                                                                                           |
  | Still redirecting after the 5th redirect          | `unchecked`, `too-many-redirects`  | Browsers allow about 20, so a 6- to 20-hop chain may work for students. Gray is honest; yellow would be wrong. |
  | 429                                               | `unchecked`, `rate-limited`        | The site is fine; we were throttled.                                                                           |
  | 400-599 (401, 403 and 5xx included)               | `broken`, with the status          | The prototype's `STATUS_TEXT`. YouTube oEmbed returns 401 or 403 for a private video.                          |
  | Below 200 or above 599                            | `unchecked`, `network-error`       | Not a real answer.                                                                                             |
  | DNS `ENOTFOUND`                                   | `broken`, status `null`            | The domain doesn't exist, and a student would get a dead link (Open Question 2).                               |
  | Refused address at preflight or in `safeLookup`   | `refused`, `private-address`       | D6.                                                                                                            |
  | Other errors (`ECONNREFUSED`, `ECONNRESET`, TLS…) | `unchecked`, `network-error`       | Often transient, or a browser would cope (incomplete certificate chains).                                      |
  | The 5 s per-URL timer, or the budget, fires       | `unchecked`, `timeout` or `budget` | The ticket: never broken.                                                                                      |

  **HEAD → GET:** retry with GET on HEAD ≥ 400 except 429, not only on 405 and 501. Many servers answer HEAD wrongly with 403 or 404 (presigned URLs, bot rules), so retrying cuts false "broken" results. The cost is a second request, and only for URLs that already look broken. The fallback is per hop. Both requests share the URL's 5 s.

- **D6. A fourth result, `refused`, kept apart from couldn't check (recommended; Open Question 1).**

  - The ticket lists three results. But the prototype shows a refused address as **yellow** ("wasn't fetched: private or internal address"), while ODY-793 says couldn't check must be **gray**.
  - If refused were folded into couldn't check, a `localhost` image would show gray, and ODY-793's "same result as the prototype" check could fail.
  - `refused` is also stable and the creator can fix it, unlike a timeout.
  - A separate `kind` makes ODY-793's `switch` exhaustive, so this can't be missed.
  - **Alternative:** keep three kinds, `{ kind: "unchecked", reason: "private-address" | … }`, and have ODY-793 special-case the refused reasons.

- **D7. The API is a per-scan fetcher, with `checkUrls` as a thin batch wrapper.**

  - **`createSafeFetcher(options?)`** returns a `FetchUrl`. It owns the cache (`Map<string, Promise<UrlCheck>>`), the queue, the active count and one deadline (`now + budgetMs` at creation).
    - This is what ODY-790's `runChecks(doc, checks, fetchUrl)` and the prototype's `makeSafeFetcher` expect.
    - Rules call `fetchUrl` lazily, and the Images `loads` and `size` rules share one request through the cache.
  - **`checkUrls(urls, options?)`** creates one fetcher, awaits all the URLs and returns `Map<input, UrlCheck>`. This is the ticket's API, and handy for tests.
  - **Scheduling:**
    - A dequeued job whose deadline has passed resolves `budget` straight away.
    - Each job's timer is `min(urlTimeoutMs, deadline - now)`. It aborts with `"timeout"` or `"budget"`, whichever bound was smaller when the job started.
    - The timer is cleared in `finally`, so Jest has no open handles.
    - So the scan never takes much more than 20 s, even when every socket hangs.
  - **ODY-794** creates the fetcher right before `runChecks`, so the 20 s starts with the checks.

- **D8. Server-only, and not a Server Action.**

  - `import "server-only";` goes on line 1. No dependency is needed (Next aliases it and `next/jest` mocks it).
  - There's no `"use server"`, so the guard test doesn't scan the file and no export becomes an endpoint.
  - **ODY-793's `rules/media.ts` and ODY-790's `types.ts` use `import type` only.** Type imports are erased, so rule tests never load `node:http`.
  - **Gotcha:** if root `npm run lint` or the type check complains about the `server-only` import, stop and ask. Don't add a dependency without approval. The fallback is the `review-freeze.ts` convention (a header comment, no import).

- **D9. The test seams use dependency injection, not `jest.mock` of Node modules.**

  - `SafeFetcherOptions` has three optional fields:
    - **`lookup`:** a `net.LookupFunction`, default `dns.lookup`. Tests pass a fake resolver, and the real `http.request` and `safeLookup` still run, so the pinning is tested for real.
    - **`send`:** one HTTP request, default `nodeSend`. Tests pass a fake to drive status codes, redirects, slow servers and concurrency with fake timers.
    - **`limits`:** a partial override of `NETWORK_LIMITS`.
  - The seams only make the fetcher _more_ restrictive or fake. There is no option to skip `isPublicAddress`, so no caller can switch the SSRF guard off.
  - **The headers test** uses `jest.spyOn(http, "request")` with a fake `ClientRequest`. `network.ts` must `import http from "node:http"` (and `https`) and call `http.request` at call time. Babel's `import * as` copies the module's properties, so a spy wouldn't see the calls.

- **D10. Limits live in `network.ts` for now.** `NETWORK_LIMITS = { urlTimeoutMs: 5000, maxConcurrent: 6, budgetMs: 20000, maxRedirects: 5 }`.

  - ODY-790's `config.ts` lists "every limit from CONFIG", but `config.ts` must never import `network.ts`, because `server-only` would then poison any client import of the config.
  - **If `config.ts` is on develop when this is built,** move the four numbers there and import them into `network.ts`.
  - **Otherwise** ODY-790 moves them later. Say so in the `[CONTRACT]` post.
  - `maxImageBytes` belongs to ODY-793's rule, not the fetcher.

```ts
// frontend/lib/overview-scan/network.ts (server only; import types with `import type`)

export type RefusedReason =
  | "invalid-url" // not an absolute URL (relative URLs included)
  | "unsupported-scheme" // not http: or https:
  | "private-address"; // the host, a resolved address or a redirect target isn't public

export type UncheckedReason =
  | "timeout" // the URL's 5 s ran out
  | "budget" // the scan's 20 s ran out first
  | "too-many-redirects" // still redirecting after 5 redirects
  | "rate-limited" // 429
  | "network-error"; // connection reset or refused, TLS failure, odd status

export type UrlLoaded = {
  kind: "loaded";
  finalUrl: string; // after redirects
  status: number; // 2xx, or a 3xx with no Location
  contentType: string | null; // lowercased media type, no parameters
  bytes: number | null; // Content-Length, or null when absent
};

export type UrlBroken = {
  kind: "broken";
  finalUrl: string;
  status: number | null; // 4xx or 5xx; null = the host doesn't exist
};

export type UrlRefused = {
  kind: "refused";
  finalUrl: string; // the URL that was refused (a redirect target, perhaps)
  reason: RefusedReason;
};

export type UrlUnchecked = {
  kind: "unchecked";
  finalUrl: string;
  reason: UncheckedReason;
};

export type UrlCheck = UrlLoaded | UrlBroken | UrlRefused | UrlUnchecked;

export type FetchUrl = (url: string) => Promise<UrlCheck>; // never rejects

export type NetworkLimits = {
  urlTimeoutMs: number;
  maxConcurrent: number;
  budgetMs: number;
  maxRedirects: number;
};

export const NETWORK_LIMITS: NetworkLimits = {
  urlTimeoutMs: 5_000,
  maxConcurrent: 6,
  budgetMs: 20_000,
  maxRedirects: 5,
};

export type SafeFetcherOptions = {
  lookup?: LookupFunction; // from "node:net"; tests only
  send?: Send; // tests only
  limits?: Partial<NetworkLimits>;
};

export function createSafeFetcher(options?: SafeFetcherOptions): FetchUrl;

export function checkUrls(
  urls: readonly string[],
  options?: SafeFetcherOptions,
): Promise<Map<string, UrlCheck>>;

export function isPublicAddress(ip: string): boolean;
```

**How ODY-793 maps the results, matching the prototype's `fetchFlag`:**

- **`loaded`:** apply the rule's own test (`contentType?.startsWith("image/")`, `bytes > maxImageBytes`). With `bytes === null`, there's no size flag.
- **`broken`:** yellow. "doesn't load (404 Not Found)", or "the site doesn't exist" when `status === null`.
- **`refused`:** yellow. "wasn't fetched: private or internal address" or "not a web address" (the prototype's `blocked`).
- **`unchecked`:** the check reports couldn't check (gray). `timeout` reads "didn't answer within 5 s"; `budget` reads "wasn't checked before the scan's time ran out".

**For ODY-790:** `run.ts` and `types.ts` take `fetchUrl: FetchUrl` via `import type { FetchUrl } from "./network"`. If ODY-790 lands first with its own placeholder type, the second PR to land aligns it to this one.

**For ODY-794:** call `createSafeFetcher()` immediately before `runChecks`, once per scan. Never call it from a client component or a `"use server"` export without the scan's auth and rate limit in front.

**Handoff notes (not this ticket):**

- **Local datasets** have relative `/uploads/…` URLs, which come back `refused` / `invalid-url`. ODY-793 should skip URLs that aren't absolute, or report them as couldn't check, rather than resolve them against the app origin. That origin is `localhost` in dev and would be refused anyway.
- **`mailto:` links** come back `unsupported-scheme`. ODY-793 decides whether to fetch only `http(s)` links (the prototype flags them).

- [ ] **Task 3: The fetcher (queue, budget, redirects, HEAD → GET, outcomes)** (depends on Task 2)

  - **Read:** D5, D6, D7 and the Contract; the prototype's `makeSafeFetcher` (~1410-1454).
  - **Modify:** `network.ts` and its test.
  - **What:**
    - **`checkOne(input, signal, send)`:**
      1. Run `preflight`.
      2. Loop over hops 0 to `maxRedirects`:
         - Send HEAD. If its status is ≥ 400 and not 429, send GET to the same URL.
         - If the status is 3xx with a `location`:
           - on the last hop, return `too-many-redirects`;
           - otherwise `preflight(new URL(location, url).href)`; if that's refused, return it (with `finalUrl` = the target); otherwise continue.
         - Otherwise map the status per D5.
      3. On a thrown error, map it in this order:
         1. `signal.aborted`: `unchecked` with `signal.reason` (`"timeout"` or `"budget"`);
         2. `RefusedAddressError`: `refused` / `private-address`;
         3. `code === "ENOTFOUND"`: `broken`, status `null`;
         4. anything else: `unchecked` / `network-error`.
    - **`createSafeFetcher(options)`:**
      - Merge the limits. Set `deadline = Date.now() + budgetMs`.
      - Keep the cache, the queue and an `active` count, and `pump()` up to `maxConcurrent`.
      - **Each job:**
        - Compute `remaining = deadline - Date.now()`. At or below 0, resolve `budget`.
        - Otherwise create an `AbortController` and `setTimeout(() => ac.abort(reason), Math.min(urlTimeoutMs, remaining))`, with the reason chosen per D7.
        - Run `checkOne`, then `clearTimeout` in `finally`.
      - `fetchUrl` never rejects: catch everything and map it to `network-error`.
    - **`checkUrls`:** `new Map(await Promise.all(unique(urls).map(async (u) => [u, await fetchUrl(u)])))`.

## Open Questions (defaults are in the plan; say if you want otherwise)

1. **A fourth result, `refused` (D6).** The ticket lists three. Recommended: keep `refused` separate, so ODY-793 shows it yellow, as the prototype does. The alternative folds it into couldn't check with a reason code.
2. **"No such host" counts as broken (yellow)** rather than couldn't check (D5). Transient DNS failures (`EAI_AGAIN`) stay couldn't check.
3. **All 5xx count as broken**, matching the prototype's 500. The alternative treats 502, 503 and 504 as couldn't check, since they're often brief outages.
4. **An honest `User-Agent`** (`OdysseyScan/1.0`). Some sites behind Cloudflare return 403 to non-browser agents, which would flag yellow. A browser-like UA cuts that but misrepresents us. The recommendation is the honest one.
5. **No body reads, so `bytes` is `null` without `Content-Length`** (D4). That's fine for Odyssey's S3 and CloudFront media, but an external chunked image over 2 MB won't be flagged.
6. **Defense in depth outside the code:** an ECS egress rule or proxy that blocks `169.254.169.254` and the VPC range for this traffic. It's terraform, so it'd be a separate ticket for whoever owns infra. Also confirm the ECS task role is scoped tightly, since IMDS/task-metadata credentials are what an SSRF goes after.
