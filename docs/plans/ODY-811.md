# ODY-811: Taking over a lesson's edit lock saves an old copy over newer edits

Base: ODY-810 branch (`de9f7c5a`, develop `e6754c59` + ODY-810, Strapi v5). Must not undo ODY-810 D11 (after a review ends, a tab shows Reload and never auto-acquires), the frozen-creator rule, or the unknown-review guard.

## Root cause

`gainLock()` in `hooks/useEditingLock.ts` sets `isOwnLock: true` immediately, and nothing reloads the lesson. Only the first acquire in `init` is safe (the server-rendered content is seconds old). The poll takeover, the reviewer's `startEditing` and the poll taking back a lock lost to a failed heartbeat all turn the tab editable on content from when the page loaded. `LessonRenderer` then:

- mounts BlockNote once (`key=editor-${lesson.id}`, `initialContent={lesson.blocksV2}`);
- seeds v1 `blocks`, `name` and `editorVersion` from props;
- autosaves the whole document.

So B's first keystroke saves B's stale document over A's edits.

## Design

1. **Hook.** `useEditingLock(lessonId, refresh?)`. Every lock gained after `init`'s first acquire runs `takeOver()`:
   - acquire the lock, keep it (heartbeat starts), stay read-only (`isOwnLock` false, `isRefreshing` true);
   - `await refresh(previousHolder)`, guarded by the mounted checks;
   - on success call `gainLock()`;
   - on failure or throw, release the lock (`dropLock`) and stay read-only; the next poll retries;
   - `previousHolder` (who held the lock before) is remembered from the poll and exposed as `tookOverFrom`.
   - ODY-810 rules stay as they are: no acquire when frozen, no auto-acquire after `reviewEnded`, none while the review state is unknown. The review state is re-checked after the refresh; if it turned frozen or ended, the lock is dropped instead of gained.
2. **Server action** `getLatestLessonContent(lessonId)` in `lib/requests/lesson.ts`: `withAuth([])`, `isValidId`, `checkLessonWrite`, then an uncached `fetchAPI("/lessons")` for `name`, `blocksV2`, `blocksVersion` and `blocks` (with `LESSON_BLOCKS_POPULATE`).
3. **Renderer.**
   - `refreshLesson` cancels pending debounces, calls the action, replaces `blocks`, `lastSavedBlocks`, `name`, `editorVersion` and a new `blocksV2` state, and bumps a `contentVersion` used in the BlockNote `key`.
   - It resolves only after the state is applied.
   - BlockNote's `onChange` only subscribes after its own 150 ms ready delay and fires only on editor transactions, so a remount of unchanged content does not autosave.
   - After a takeover from another person, a `role="status"` notice says "<First Last> finished editing. You're now editing the latest version."; with no known holder: "You're now editing the latest version."

## Tests (written first)

- Hook (`testing/hooks/use-editing-lock.test.ts`): poll takeover awaits refresh before `isOwnLock`; failed refresh releases the lock and stays read-only, next poll retries; `startEditing` refreshes; the init acquire does not refresh; a frozen result after refresh drops the lock.
- Renderer (`tests/components/draft/lesson-renderer.test.tsx`): after a takeover the editor shows fresh content before it becomes editable; no `updateLesson` carries stale content; the notice text appears.
- Server action (`testing/requests/lesson-latest-content.test.ts`): refuses an invalid id, a logged-out caller and a caller without write rights; returns fresh content for an author. Query catalog entry added; no allowlist entries.
