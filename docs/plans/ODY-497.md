# ODY-497: Add filters to the Groups page

Ticket: Improvement / UI, Low priority. The ticket has only its title, so the spec below is inferred from the code on `develop` (3b1783f4) and needs Awad's approval.

## Problem

`/g/dashboard` (heading "Groups", `app/(groups)/g/dashboard/page.tsx`) lists every group the signed-in user belongs to, but the only way to narrow the list is the role tabs. A faculty member or content creator who runs many sections across semesters has to page through cards 12 at a time (`GROUPS_PER_PAGE`, `paginated-groups-grid.tsx`) to find one group. There is no search and no semester filter, although the admin table at `/admin/groups` already has both.

### What a user sees today

- **Data:** `getCachedUserGroups(userId)` → `getUserGroups` (`lib/requests/groups.ts:196`) returns every group where the user is creator, admin, manager or member. It walks all pages of 100, sorted `groupName:asc`, and returns the fields `id, groupName, slug, semester, isArchived` plus `members`, `admins`, `managers` (id, email), `creator` (id, email, firstName, lastName) and `users_archived` (id). It does **not** return `dropletDueDates`, `playlistDueDates`, `description` or any content counts. Cache tags: `CACHE_TAGS.allGroups` and `CACHE_TAGS.userGroups(id)`, TTL 900s.
- **How many:** no limit. A student usually has a handful; a faculty member can have dozens (one group per section per semester). The whole list is already in memory on the server for every render.
- **Tabs** (`group-selector.tsx`, `?tab=`, `router.push`, so a server render): Member, Admin, Creator (only for Content Creator / Faculty / SysAdmin) and Archived. `page.tsx` also accepts `manager` and `favorites` in `VALID_TABS`, but the selector shows no Manager tab, and Favorites is a "Favorites coming soon" stub. A group can show in several role tabs (for example creator and admin). Archived (per-user `users_archived` or group-level `isArchived`) groups appear only in the Archived tab, with the viewer's highest role (`lib/group-archive.ts`).
- **Sorting:** fixed `groupName:asc` from Strapi. No sort control.
- **Search:** none.
- **Pagination:** client-side, `useState` page, 12 per page, remounted on tab change (`key={tab}`), with a clamp for a shrinking list.
- **Header row:** the tabs on the left, `RefreshGroupsButton` (ODY-484, on develop) and "Create Group" on the right.
- **Other "groups" pages, not in scope:** `/admin/groups` (SysAdmin table, already has search, sort and a semester filter via `useAdminTableFilters`), `/g/[slug]` (one group), `/g/management` (create or edit form), `/g/due-dates`.

## Acceptance Criteria

- [ ] `/g/dashboard` shows a search box and a "Semester" filter between the tabs and the grid, on every tab except Favorites, when the user has at least one group.
- [ ] Typing in the search box narrows the current tab's cards to groups whose `groupName` contains the text, case-insensitive, after the 300 ms debounce. The text is mirrored to `?q=` with `replaceState` (no server render), exactly like Explore.
- [ ] The Semester filter is a multi-select that lists only semesters present in the user's groups (all tabs), in the schema's chronological order, and is stored as `?semester=Fall 2026,Spring 2027` (comma-joined, like Explore's `Filter`). A group matches if its `semester` is one of the selected values.
- [ ] Search and semester combine with AND, and both apply inside the current tab, including Archived.
- [ ] Switching tabs keeps `q` and `semester` (the selector already copies all params).
- [ ] Changing the search or the semester selection returns the grid to page 1.
- [ ] When filters leave no cards, the grid shows an empty state titled "No groups here" (same title as `page.tsx`) with the message "No groups match your search or filters." and a "Reset filters" button that clears `q` and `semester` and keeps `tab`.
- [ ] With no `q` and no `semester`, the page renders exactly as today (same cards, same order, same empty states).
- [ ] Back from `/g/[slug]` restores the search box text and the semester filter (Explore's ODY-865 behaviour: read client-written params on the client).
- [ ] No change to `lib/requests/groups.ts`, the Strapi query or cache tags.

## Out of Scope

- A role filter. Roles are already the tabs; a second role control would contradict them.
- An "archived vs active" filter. That is the Archived tab.
- "Has due dates". `getUserGroups` doesn't fetch `dropletDueDates` / `playlistDueDates`. Adding them means a bigger payload for every group read and edits `groups.ts`, which ODY-488 and security PR 8 are both changing. A follow-up ticket if wanted (Q3).
- A sort control (Q2).
- Moving the grid's page into `?page=` (`useUrlPage`). Today's `useState` page is kept.
- `/admin/groups` (already filtered) and the Favorites stub.
- The missing Manager tab (Q1).

## Design Decisions

1. **All filtering is client-side, in the grid.** The page already holds the user's full group list and the grid is already a client component that paginates it. Filtering a few dozen items in memory needs no new Strapi query, no new cache tag, and keeps `groups.ts` untouched, which avoids conflicts with ODY-488 and security PR 8. Server-side Strapi filters were rejected: `getUserGroups` walks every page anyway, and a per-filter query would split the cache for no gain.
2. **Reuse Explore's controls as they are.** `Search` (`components/explore/search.tsx`) with `ExploreSearchProvider` for `?q=`, and `Filter` (`components/explore/filter.tsx`) for `?semester=`. No new search or filter component. The admin page's `useAdminTableFilters` + `FilterButton` pattern was rejected because it keeps state in React only (lost on Back) and uses an Apply/Reset draft popover that doesn't match the student-facing pages; the ticket asks for the Explore pattern.
3. **Read both params on the client.** `q` is written with `replaceState`, so the server's `searchParams` go stale on Back (`docs/agent/learnings/2026-11-02-back-restores-stale-server-search-params.md`). The grid reads `semester` with `useSearchParams()` and `q` from `useSearch()`; `page.tsx` never reads either. `ExploreSearchProvider` already seeds the box from the live `?q=`; it is generic despite its name, so we wrap the Groups page in it rather than rename it (a rename is churn with no behaviour change).
4. **Semester options come from all of the user's groups, not the current tab,** so the control stays the same across tabs and a selected value never vanishes from the list. Order follows the schema enum (chronological) instead of the admin page's alphabetical sort ("Fall 2025" before "Spring 2025" is wrong). `SEMESTER_OPTIONS` moves from `group-management-form.tsx` to `lib/globals.ts` so both use one list. The filter is hidden when the user's groups span fewer than two semesters (one option filters nothing), unless `?semester=` is already set, so a stale URL can still be cleared.
5. **Pure helpers in `lib/group-filters.ts`.** `filterGroups` and `getSemesterOptions` are plain functions with unit tests, so the grid only wires them up.
6. **Page 1 on change.** The grid stores the last filter signature (`q` + `semester`) and resets `currentPage` to 1 when it changes, using the same render-time `setState` pattern as its existing clamp. The `key={tab}` remount stays for tabs. `Filter` already deletes `page`, harmless here.
7. **Reset reuses ODY-256's `ResetFiltersButton`.** It is hard-wired to Explore's params today. Add an optional `filterParams?: string[]` prop (default: today's Explore list) so Groups passes `["semester"]`; `q` and `page` are always cleared, everything else (`tab`, `sort`) is kept. This and `EmptyState`'s `action` prop exist only on `claude/ody-256-reset-filters`, **not yet on develop** (checked with `git branch -r --contains`, 2026-11-10). Task 4 waits for it.
8. **Search matches `groupName` only,** like `/admin/groups`. Matching the creator's name was considered; it's only shown on member cards and would make results look random on admin cards.
